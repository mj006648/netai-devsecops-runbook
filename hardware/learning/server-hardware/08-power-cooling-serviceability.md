# 08. 전원·냉각·정비성: 장착 가능과 운용 가능의 차이

이 장의 목표는 가속기 자리가 남아 있어도 전원·공기 흐름·정비 경로가 충족되지 않으면 증설을 확정할 수 없다는 점을 계산으로 이해하는 것이다.
사례의 “현재”는 [A7 실측 일지](../../npu/a7-expansion-plan-2026-09-21.md)의 2026-09-21 읽기 전용 조회를 뜻한다.
GPU 최종 4장과 RNGD 4장은 **검토 중인 배치안**이며, 추가 GPU 구매·장착 수량은 확정되지 않았다.

## 1. 서버 외형에서 시작하는 제약 지도

```text
랙 전면 / 찬 공기
  ↓
6U 섀시 ─ 전면 흡기·드라이브·PSU/팬 모듈
  ↓      메인보드: CPU 소켓 2개, DIMM 자리, 내부 전원 분배
  ↓      라이저/PCIe 스위치 보드: 카드의 높이·길이·전기 경로 결정
  ↓      덕트/블랭킹: 공기가 발열 부품을 통과하게 안내
랙 후면 / 더운 배기

랙 PDU·회로 A/B → 전원 케이블 → PSU → DC 버스 → CPU/GPU/NPU/팬
```

`U`는 랙 높이 단위로, 1U는 44.45mm다.
6U라 해도 모든 카드가 어느 슬롯에나 맞는다는 뜻은 아니다.
PCIe 커넥터, 브래킷 높이, 카드 길이, 이웃 슬롯 폭, 라이저, 에어덕트, 전원 케이블 경로를 함께 확인한다.
소켓은 CPU를 끼우는 물리 자리이고, DIMM 자리는 메모리 모듈의 자리다.
FRU(Field Replaceable Unit)는 정비 시 식별·교체하는 부품 단위이며, 논리 슬롯 번호와 반드시 1:1이 아니다.
이 모델의 제품 사양은 6U, CPU 두 개, DIMM 자리 24개를 제시한다.
[xFusion G6550 V8 제품 사양](https://www.xfusion.com/en/product/ai-servers/fusionserver-g6550-v8-ai).

A7은 CPU 소켓 두 개 모두 EPYC 9355로 사용 중이고 RAM은 128GB다.
슬롯 계획에는 큰 가속기 자리 8개를 실제 후면 배치로 매핑했지만, 빈 자리만으로 장착 가능성을 확정하지 않았다.
특히 GPU용 슬롯과 일반 NIC 후보 슬롯은 크기와 지원 라이저가 다를 수 있다.
모델 전체의 “최대 GPU/PCIe 슬롯” 광고 숫자와 납품된 섀시·보드·전원 하네스의 BOM은 별개다.
[A7의 슬롯 실측표](../../npu/a7-expansion-plan-2026-09-21.md#2-현재-슬롯-전체-지도와-조건부-배치안).

## 2. 전력 숫자 네 가지를 혼동하지 않기

| 숫자 | 무엇을 뜻하나 | 무엇을 뜻하지 않나 |
|---|---|---|
| 부품 TDP | 방열 설계에 사용하는 지속 열 부하 기준 | 모든 순간의 실제 소비전력 또는 전기적 최대값 |
| 장치 power limit | 현재 펌웨어·관리 도구에 설정된 상한 | 항상 그만큼 소비한다는 뜻 |
| 순간 power draw | 측정 시점의 실제 입력·소비 전력 | 장시간 최대 부하·냉각 검증 |
| PSU 정격 출력 | 특정 입력·환경 조건에서 제공 가능한 DC 출력 | 서버가 언제나 그 전력을 소비한다는 뜻 |

GPU 사양과 전력 제한도 같은 단어를 써서 혼동하기 쉽다.
A7의 RTX PRO 6000 Blackwell **Server Edition** 두 장은 현재/default/max power limit이 각각 600W로 조회됐고, 조회 순간 draw는 약 29W/34W였다.
NVIDIA의 해당 Server Edition 사양은 600W와 패시브 냉각을 명시한다.
[NVIDIA RTX PRO 6000 Blackwell 제품 사양](https://www.nvidia.com/en-us/products/workstations/professional-desktop-gpus/rtx-pro-6000-family/).
두 장의 낮은 순간 소비가 네 장 부하 운용 시 전원이나 풍량의 여유를 보증하지 않는다.

FuriosaAI의 현재 [RNGD 제품 페이지](https://furiosa.ai/rngd)는 180W TDP를 광고한다.
반면 A7에서 관측된 네 장의 **설정된 power limit**은 300/225/300/300W다.
두 숫자는 정의가 다르며, 225W 제한 카드의 이유와 정상 출하 조건도 아직 확인되지 않았다.
설정 상한을 실제 지속 소비나 제품 TDP로 바꾸어 적지 않는다.
어떤 전력 설정도 이 교재를 위해 변경하지 않았다.

### AC 입력과 DC 출력

PSU는 랙의 AC 전력을 서버 부품이 쓰는 DC 전력으로 변환한다.
효율 `η = DC 출력 ÷ AC 입력`이므로 `AC 입력 = DC 출력 ÷ η`다.
예를 들어 **가정**한 DC 부하 5.0kW와 효율 90%라면 AC 입력은 `5.0 ÷ 0.90 ≈ 5.56kW`, PSU 내부 손실 열은 약 0.56kW다.
이 수치는 A7 측정치가 아니라 변환 관계를 설명하는 연습이다.
효율은 부하율·입력 전압·제품에 따라 달라진다.
[미국 에너지부 데이터센터 설계 가이드](https://www.energy.gov/sites/default/files/2024-07/best-practice-guide-data-center-design.pdf).

PSU 정격을 모두 더한 수는 서버의 허용 부하가 아니다.
입력 회로가 버틸 수 있는 전류, 중복 정책, PSU 온도에 따른 디레이팅, 내부 전원 분배, 케이블도 더 낮은 한계를 만들 수 있다.
단위도 구분한다. W는 순간 전력, Wh는 일정 시간에 쓴 에너지다.

## 3. A7 증설안의 전력 예산

```text
검토안: RTX PRO 6000 Server Edition 4장 × 600W = 2,400W
        RNGD 4장 × 300W = 1,200W  ← 설계 검토를 위한 가정 상한
        ─────────────────────────────────────────
        가속기만 3,600W
      + CPU 두 개, 128GB RAM, SSD/RAID, NIC, PCIe 스위치, 팬
      + 장착 가능한 추가 NIC·메모리의 여유
      + PSU 변환 손실(AC 쪽), 고장 시 잔존 PSU 용량 조건
```

`4 × 300W`는 A7의 세 카드에서 읽힌 설정 상한을 네 장에 적용한 **보수적 설계 계산 가정**이다.
RNGD의 제품 TDP가 300W라고 확인된 숫자가 아니다.
현재 네 카드의 상한 합계는 `300 + 225 + 300 + 300 = 1,125W`지만, 225W 설정을 장래 용량 절감 보장으로 삼을 수 없다.
RNGD 제품 페이지의 `4 × 180W = 720W`도 냉각 설계 문맥의 TDP 합계이지 순간 피크 또는 노드 최대 전력 측정치가 아니다.
GPU 네 장의 2.4kW와 NPU 계산 가정 1.2kW 사이의 차이를 제품 간 우열 비교로 해석하지 않는다.

A7의 DCMI 조회는 약 17:03 KST에 **798W 순간값**이었다.
두 GPU가 저부하 상태인 그 시점의 노드 소비이므로 증설 후 고부하, 팬 상승, 한쪽 전원 계통 장애 상황을 대표하지 않는다.
GPU·NPU를 전부 최대 부하로 동시에 돌려서 검증한 기록도 없다.
전원 계획은 각 부품의 입력 사양, 실제 제한값, 동시 부하 가능성, OEM 지원 구성, 예비량을 하나의 시트에서 대조해야 한다.

## 4. PSU가 여덟 개면 무엇을 알 수 있나

A7 BMC는 PSU 8개 모두 `Presence detected`, 상태 `ok`로 보고했고, FRU는 `PAC3K2S12-TG`였다.
각 입력은 약 222V, `PS Redundancy` 센서는 `ok`였다.
이 사실은 **현재 감지·건강 상태**를 말한다.
정확한 장착 PSU의 출력 정격, 해당 입력 전압에서의 허용 출력, 실제 입력 feed 배선, 중복 운용 정책은 실측 일지만으로 확정되지 않았다.

[xFusion의 현행 G6550 V8 제품 페이지](https://www.xfusion.com/en/product/ai-servers/fusionserver-g6550-v8-ai)는 `8 × 3200W` PSU와 N+N 중복 구성을 설명한다.
이는 제품군의 제공 사양이며, A7의 해당 FRU와 입력 조건에서 8개 모두 3200W를 사용할 수 있다는 증명은 아니다.
제품의 공장 구성표와 PSU 라벨·부품 사양·BMC 전력 한계 설정을 대조해야 한다.

| 중복 방식 | 뜻 | 8개 동일 PSU, 각 정격 `P`인 예 |
|---|---|---|
| N+1 | 필요한 N개 외에 한 개의 예비 | 7개 분량 `7P` 이하를 1개 고장 조건에서 검토 |
| N+N | 필요한 용량을 두 그룹이 각자 제공 | 4+4라면 한쪽 그룹만으로 부하를 감당해야 하므로 `4P` 이하를 검토 |
| 2N 전원 경로 | PSU 그룹뿐 아니라 상위 경로도 두 벌 | 회로·PDU·UPS·배선의 분리까지 확인 |

표는 정의를 익히기 위한 이상적 예이며, A7이 실제로 어느 정책인지 확인한 값이 아니다.
N+1에서 7개가 살아남아도 모두 같은 PDU 한 대에 연결됐다면 그 PDU 장애에는 취약하다.
N+N에서도 두 그룹을 결국 같은 회로에 꽂으면 feed 장애 도메인은 분리되지 않는다.
PSU 중복은 **PSU 장애**와 **전원 경로 장애**를 따로 그려서 검토해야 한다.

```text
바람직한 분리의 개념도(현재 A7 배선이라는 뜻 아님)
회로 A → UPS/PDU A → PSU 그룹 A ┐
                                 ├→ 공통 서버 DC 버스
회로 B → UPS/PDU B → PSU 그룹 B ┘
```

랙 PDU의 콘센트·케이블 정격과 차단기, 상위 회로까지 전류와 열 기준으로 확인한다.
플러그가 물리적으로 맞는다는 이유만으로 정격이나 배선 호환성이 성립하지 않는다.
서버 내부 GPU/NPU 보조 전원 커넥터는 더 엄격하다. 같은 모양의 커넥터라도 핀 배열, 접점 정격, 센스 핀, 케이블 규격이 다를 수 있다.
정확한 카드 P/N, 서버 OEM 승인 하네스·라이저·전원 보드 문서로 조합을 검증한다.
임의 어댑터나 다른 장비 케이블을 모양만 보고 사용하지 않는다.

## 5. 팬과 공기 흐름은 한 시스템이다

패시브 GPU는 카드에 자체 팬이 없고, 서버 팬이 만든 규정된 흐름과 압력에 의존한다.
NVIDIA는 RTX PRO 6000 Blackwell Server Edition을 패시브 열 설계로 표기한다.
[NVIDIA 공식 사양](https://www.nvidia.com/en-us/products/workstations/professional-desktop-gpus/rtx-pro-6000-family/).
카드 한 장을 더 넣으면 소비전력뿐 아니라 공기 저항, 이웃 카드의 흡기, 팬 제어도 달라진다.

```text
찬 통로 → 전면 흡기 → 서버 팬 → 덕트 → GPU/NPU 방열판 → 후면 배기 → 더운 통로
                              ↘ 빈 구멍·빠진 블랭킹 → 우회 흐름 → 발열부 냉각 감소
```

에어덕트는 바람을 필요한 부품으로 이끌고, 빈 베이 블랭킹은 공기가 쉬운 우회로로 빠지지 않게 한다.
랙 앞뒤의 냉·온 통로 분리도 재순환을 줄인다.
[ASHRAE 데이터센터 공조 지침](https://handbook.ashrae.org/Handbooks/A23/SI/A23_Ch20/a23_ch20_si.aspx)은 빈 랙 공간의 블랭킹을 강조한다.
서버의 OEM GPU 키트가 요구하는 팬·덕트·블랭킹·카드 순서를 확인해야 한다.

A7에서는 `Fan1–24`의 F/R 속도 센서가 모두 `ok`였고, 흡기·배기는 대략 17°C/20°C였다.
F/R은 한 팬 또는 팬 모듈의 전·후 속도 감지처럼 여러 센서 위치를 가리킬 수 있다.
**센서 24개를 독립 팬 모듈 24개라고 세지 않는다.**
xFusion 백서는 팬 모듈과 내부 팬 층을 구분해 설명한다.
[G6550 V8 기술 백서, Fan Modules](https://www.xfusion.com/wp-content/uploads/2025/11/FusionServer-G6550-V8-Server-Technical-White-Paper.pdf).
낮은 부하의 `ok`와 차가운 흡기만으로 장시간 고부하에서의 GPU 핫스팟·스로틀링 여유를 판정할 수 없다.

### 액체 냉각 용어도 정확히 구분하기

직접 칩 냉각은 CPU/GPU에 닿은 **콜드플레이트**에 냉각액을 흘려 열을 받는다.
CDU(Coolant Distribution Unit)는 서버 측 냉각액의 순환·제어와 시설 측 열 교환을 맡는 장치다.
콜드플레이트와 CDU는 같은 부품이 아니다.
액체 냉각을 채택해도 PSU·SSD 등 공랭이 남을 수 있다.
[Vertiv의 직접 칩 냉각·CDU 설명](https://www.vertiv.com/499174/globalassets/shared/vertiv-coolchip-cdu-br-en-gl-sl-80233-web.pdf).
A7의 현재 G6550 V8은 공랭 서버이며, 위 용어는 대안 기술을 이해하기 위한 비교다.

## 6. BMC가 보이는 것과 OS가 보이는 것

BMC는 호스트 OS와 별도로 작동하는 관리 컨트롤러다.
전원 상태, PSU/팬/온도 센서, FRU, 이벤트 로그, 원격 콘솔 등을 호스트가 부팅하지 않아도 제공할 수 있다.
Redfish는 HTTP 기반의 표준 관리 모델이고, IPMI는 다른 관리 인터페이스다.
둘 다 플랫폼 펌웨어·BMC의 지원 범위 안에서 제공된다.
[DMTF Redfish 리소스 가이드](https://www.dmtf.org/sites/default/files/standards/documents/DSP2046_2023.3.html), [xFusion 제품 관리 사양](https://www.xfusion.com/en/product/ai-servers/fusionserver-g6550-v8-ai).

OS의 `lspci`, 드라이버 상태, GPU/NPU 도구는 부팅한 호스트가 실제로 본 장치와 링크를 보여 준다.
BMC 센서가 `ok`여도 OS 드라이버가 로드되지 않거나 장치 통신이 실패할 수 있다.
반대로 OS에 카드가 보여도 PSU feed 또는 팬의 단일 고장 여유가 확인된 것은 아니다.
BIOS/UEFI는 호스트의 초기화·부팅을 담당하는 펌웨어, BMC 펌웨어는 관리 컨트롤러의 소프트웨어, 드라이버는 OS가 장치를 쓰게 하는 코드다.
버전도 각각 관리해야 하며 한쪽 업데이트가 다른 쪽 검증을 대신하지 않는다.

| 관측 | 입증하는 범위 | 추가로 필요한 질문 |
|---|---|---|
| PSU presence/health `ok` | 현재 모듈 감지와 자체 상태 | 한 feed 장애 때 허용 부하는? |
| 팬 속도·온도 `ok` | 조회 시점의 센서 범위 | 실제 모델 부하에서 스로틀링은? |
| `lspci`에 GPU 표시 | OS가 PCIe 장치를 열거 | 드라이버·전원·장시간 작업은 정상인가? |
| 저부하 798W | 그 순간 노드 전력 | 동시 부하·시동 과도·장애 시 피크는? |

실제 검증은 승인된 작업 시간에 대표 워크로드로 전력, 온도, 팬 속도, 스로틀링, 오류를 같은 타임라인에 기록하는 방식이어야 한다.
A7에서는 그 부하 검증을 수행하지 않았다.

## 7. 정비 가능한 설계와 현장 순서

정비성은 “부품을 빼기 쉽다”보다 넓다.
정확한 FRU와 슬롯을 식별하고, 장애 영향 범위를 알고, 교체 후 경로와 상태를 재검증할 수 있어야 한다.
핫스왑 지원 PSU라고 해서 어떤 부하·전원 정책에서나 모듈을 빼도 안전한 것은 아니다.
RAID 멤버도 잘못 식별해 정상 드라이브를 빼면 서비스 손실을 만들 수 있다.

현장 유지보수를 계획할 때의 안전한 순서는 다음과 같다.

1. 변경 대상의 서버 자산 ID, 슬롯/FRU, 케이블·PDU 포트, 작업 목적을 사전에 대조한다.
2. 백업·복구 준비와 서비스 영향, 유지보수 창, 원격 접속·롤백 경로를 확인한다.
3. BMC와 OS의 현재 상태, RAID 멤버, 전원·팬 센서, 펌웨어·드라이버 버전을 기록한다.
4. 정확한 OEM 절차에 따라 필요한 종료·전원 격리·ESD 조치를 수행하고 부품을 교체한다.
5. 커넥터·덕트·블랭킹·케이블 간섭과 팬 경로를 확인한 뒤 전원을 복구한다.
6. BMC health와 OS 인식, 링크·장치 경로, RAID/파일시스템, 서비스·부하 상태를 다시 대조한다.

이 목록은 현장 작업 허가가 아니며 A7 장비에는 적용·실행하지 않았다.
세부 순서는 정확한 섀시·부품의 OEM 서비스 절차와 사이트 전기 안전 규정이 우선한다.
특히 “콜드 부팅”은 팀마다 **OS 종료 후 전원 재인가**, **BMC의 PowerCycle**, **AC feed까지 분리한 완전 전원 방전** 등 다르게 쓸 수 있다.
작업 요청서에는 실제 필요한 전원 경계와 유지 시간, 두 feed의 격리 범위를 명시해야 한다.
Redfish의 `PowerCycle`은 시스템 전원 사이클 동작으로 정의되지만, 곧바로 모든 AC 입력 분리를 보증하지 않는다.
[DMTF ComputerSystem Reset 정의](https://redfish.dmtf.org/schemas/v1/DSP0268_2025.2.pdf).

## 8. 읽기 전용 관측과 흔한 오해

다음 조회는 [A7 조사에서 실제 사용한 명령](../../npu/a7-expansion-plan-2026-09-21.md)이다.
로그에는 시리얼·식별자가 들어갈 수 있으므로 공유할 때 필요한 값만 남긴다.

```bash
sudo ipmitool fru print
sudo ipmitool sdr type 'Power Supply'
sudo ipmitool sensor list
sudo ipmitool dcmi power reading
nvidia-smi --query-gpu=name,pci.bus_id,memory.total,power.limit,power.default_limit,power.max_limit,power.draw,temperature.gpu --format=csv
```

`fru print`는 모델 식별, `sdr`·`sensor`는 감지·건강 상태, `dcmi power reading`은 조회 시 전력의 출발점이다.
`nvidia-smi`의 limit와 draw는 별도 열이므로 한 값으로 합치지 않는다.
이 명령은 조회만 한다. 팬 제어, 전원 차단, BIOS 설정, 장치 전력 제한 변경은 포함하지 않는다.

| 오해 | 바로잡기 |
|---|---|
| “PSU 8개 모두 `ok`면 8×3200W를 쓸 수 있다.” | 실제 FRU 정격, 입력 조건, 중복 정책, 회로 용량은 아직 미확인이다. |
| “798W이므로 4 GPU 증설 후에도 전원 여유가 크다.” | 저부하 순간값이다. 4 GPU의 설정 상한 합만 2.4kW다. |
| “팬 센서 24개는 팬 모듈 24개다.” | 전·후 센서와 물리 모듈 수를 구분한다. |
| “패시브 GPU는 자체 발열 관리가 필요 없다.” | 서버 팬·덕트·블랭킹에 더 의존한다. |
| “BMC에서 PowerCycle하면 AC가 완전히 끊겼다.” | 시스템 동작과 시설 feed 분리는 다른 경계다. |

## 9. 연습문제

1. GPU 4장에 각각 600W를 배정하면 GPU 부분의 설계 계산은 얼마인가? 여기에 NPU를 `4 × 300W`로 가정하면 가속기 합계는?
2. 같은 정격 PSU 8개를 4+4 N+N으로 운영한다. 한쪽 feed가 사라졌을 때 단순 합산 `8P`를 허용 부하로 써도 되는가?
3. BMC가 팬·PSU `ok`이고 GPU 온도가 저부하에서 낮다. 냉각 검증을 마쳤는가?
4. “콜드 부팅 후 확인”이라는 요청에서 가장 먼저 명확히 해야 할 전원 경계는 무엇인가?

**답:** ① 2,400W와 3,600W다. 뒤 숫자의 NPU 부분은 300W 설계 가정이지 제품 TDP 확정값이 아니다. ② 아니다. 남은 4개와 그 feed가 전체 부하를 견뎌야 한다. ③ 아니다. 대표 부하의 온도·팬·스로틀링을 봐야 한다. ④ OS 재시작인지, 시스템 PowerCycle인지, 두 AC feed 격리까지 필요한지다.
