# 00. 구조와 실행 지도

[← 목차](README.md) · [다음 →](01-digital-logic-and-clock.md)

컴퓨터 구조는 프로그램의 명령과 그것을 실행하는 장치 사이의 약속을 다룬다. **ISA(Instruction Set Architecture, 명령어 집합 구조)**는 명령·레지스터·메모리·예외의 약속이고, **마이크로아키텍처(microarchitecture)**는 그 약속을 구현하는 내부 방법이다. **레지스터(register)**는 CPU 안에서 계산에 쓰는 값을 담는 작은 저장 공간이다. **컴파일러(compiler)**는 소스 코드를 실행에 쓸 코드로 바꾸고, **로더(loader)**는 실행 파일을 프로세스의 주소 공간에 배치한다.

![실행 지도](assets/execution-map.svg)

## 한 줄의 코드가 기계 상태 변화가 되는 전체 지도

컴퓨터 구조는 CPU 부품 이름 목록이 아니다.
프로그램의 뜻이 어떤 계약을 거쳐 비트가 되고, 그 비트를 회로가 읽어 레지스터와 메모리 상태를 어떻게 바꾸는지 설명하는 연결 지도다.

소스 코드 `c = a + b`를 생각하자.
컴파일러는 변수의 위치와 목표 ISA를 고려해 load, add, store 같은 명령을 고른다.
ISA는 이 명령의 비트 모양과 실행 뒤 보여야 할 레지스터·메모리 결과를 정의한다.
마이크로아키텍처는 그 약속을 파이프라인, 캐시, 실행 장치로 구현한다.

```mermaid
flowchart LR
  S[소스 c=a+b] --> C[컴파일러]
  C --> B[기계어 바이트]
  B --> L[로더가 가상주소에 배치]
  L --> F[CPU가 PC로 fetch]
  F --> D[decode]
  D --> E[execute]
  E --> M[레지스터·메모리 결과]
```

## 실제 주소 하나를 따라가기

가상주소 `0x400100`에 32비트 명령이 있고 PC가 그 주소를 가리킨다고 하자.
명령의 교육용 뜻은 `ADD r3,r1,r2`이고 현재 `r1=7`, `r2=5`다.

| 순서 | 주체 | 입력 상태 | 중간 상태 | 결과 |
|---:|---|---|---|---|
| 1 | fetch 장치 | PC=`0x400100` | MMU·캐시를 통해 4바이트 요청 | 명령 비트 획득 |
| 2 | PC 갱신 논리 | 현재 PC와 명령 길이 4 | `0x400100+4` | 다음 PC=`0x400104` |
| 3 | decoder | 명령 비트 | opcode=ADD, src=1·2, dst=3 | 제어 신호 생성 |
| 4 | 레지스터 파일 | 번호 1과 2 | 값 7과 5 읽음 | ALU 입력 준비 |
| 5 | ALU | 7, 5 | 이진 덧셈과 carry 전달 | 결과 12 |
| 6 | 완료 경로 | 목적 번호 3, 값 12 | 예외 여부 확인 | `r3=12` |

이 표는 명령 하나의 프로그램에 보이는 의미를 보여 준다.
실제 CPU는 여러 명령을 겹치거나 결과를 ROB에 먼저 둘 수 있다.
그러나 명령이 정상 retire했다면 프로그램이 보는 결과는 `r3=12`, 다음 순차 PC `0x400104`와 맞아야 한다.

두 번째 예로 `LOAD r4,8(r5)`에서 `r5=0x1000`이라 하자.
주소 계산 장치는 `0x1000+8=0x1008`을 만든다.
MMU는 이 가상주소를 물리주소로 번역하고 read 권한을 확인한다.
캐시 hit이면 해당 바이트를 고르고, miss이면 아래 계층에서 cache line을 가져온다.
주소 `0x1008`에 32비트 값 99가 있다면 정상 완료 후 `r4=99`가 된다.

여기서 “메모리”는 하나의 속도인 상자가 아니다.
레지스터, 여러 cache, DRAM, 저장장치는 용량·지연·지속성이 다르다.
load가 저장장치를 매번 직접 읽는다는 설명은 틀리다.
이미 매핑되고 메모리에 있는 페이지를 보통 cache 계층을 통해 읽는다.

ISA와 제품 구현도 구분한다.
ISA는 ADD가 어떤 결과와 예외를 보여야 하는지 약속한다.
한 제품이 ADD를 몇 단계로 나누는지, 어떤 크기의 cache를 쓰는지는 마이크로아키텍처 선택이다.
같은 ISA 프로그램이 서로 다른 구현에서 실행될 수 있는 이유가 이 경계다.

## 문제와 풀이

### 문제 1
PC가 `0x8000`, 고정 명령 길이가 4바이트일 때 순차 다음 PC는?

**풀이:** byte-addressed 주소에서 4바이트 뒤는 `0x8004`다.
분기나 예외가 없다면 fetch 뒤 순차 PC 후보가 된다.

### 문제 2
`LOAD r2,12(r1)`에서 `r1=0x2000`, 그 주소의 값이 30이면 결과는?

**풀이:** 유효주소는 `0x2000+0xC=0x200C`다.
번역과 read 권한 검사가 성공하고 메모리 계층이 값 30을 돌려주면 `r2=30`이다.
PTE 권한이 없으면 값을 기록하지 않고 fault 경로로 간다.

### 문제 3
같은 ISA의 CPU A는 5단계, B는 더 깊은 파이프라인이다. ADD 결과가 달라도 되는가?

**풀이:** 정상 retire한 프로그램에 보이는 결과는 달라서는 안 된다.
주기 수, 내부 래치, 전력과 처리량은 달라도 ISA가 약속한 입력 7+5의 결과 12는 같아야 한다.
