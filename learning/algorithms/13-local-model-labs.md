## 1. 이진 검색 모델

함수 계약은 정렬된 키 배열 keys와 찾을 값 target을 받아, 찾으면 인덱스와 추적 목록을 돌려주고 없으면 None과 추적 목록을 돌려주는 것이다. 인덱스는 배열 첫 칸을 0으로 세는 위치 번호다. 추적 목록의 한 항목은 (lo, mid, hi)다. lo와 hi는 아직 답일 수 있는 닫힌 구간의 양 끝, mid는 가운데 위치다.

~~~python
def binary_search(keys, target):
    lo, hi = 0, len(keys) - 1
    trace = []
    while lo <= hi:
        mid = (lo + hi) // 2
        trace.append((lo, mid, hi))
        if keys[mid] == target:
            return mid, trace
        if keys[mid] < target:
            lo = mid + 1
        else:
            hi = mid - 1
    return None, trace
~~~

첫 줄에서 hi가 마지막 유효 인덱스인 len(keys)-1인 이유는 닫힌 구간을 쓰기 때문이다. while 조건 lo <= hi는 lo==hi인 마지막 한 칸도 검사한다. //는 나눗셈의 소수 부분을 버려 정수 인덱스를 만든다. 가운데 값이 target보다 작으면 정렬 전제에 따라 mid 이하를 모두 버리고 lo를 mid+1로 옮긴다. 크면 mid 이상을 버리고 hi를 mid-1로 옮긴다. 매 반복마다 후보 칸 수가 줄어 종료한다.

입력 keys=[3,8,12,20,31,44,57,91], target=44의 전체 상태는 다음과 같다.

| 반복 | lo | mid | hi | keys[mid] | 판단 | 다음 상태 |
|---:|---:|---:|---:|---:|---|---|
| 1 | 0 | 3 | 7 | 20 | 20<44 | lo=4 |
| 2 | 4 | 5 | 7 | 44 | 같음 | 인덱스 5 반환 |

출력은 (5, [(0,3,7),(4,5,7)])이다. 코드의 assert는 인덱스가 5이고 추적이 이 두 튜플인지 검사한다.

없는 값 target=43도 끝까지 본다.

| 반복 | 후보 인덱스 | mid 값 | 판단 | 남은 후보 |
|---:|---|---:|---|---|
| 1 | 0..7 | 20 | 작음 | 4..7 |
| 2 | 4..7 | 44 | 큼 | 4..4 |
| 3 | 4..4 | 31 | 작음 | 5..4, 빈 구간 |

lo=5, hi=4가 되어 while을 끝내고 (None, [(0,3,7),(4,5,7),(4,4,4)])를 반환한다. 빈 배열이면 처음부터 lo=0, hi=-1이라 반복하지 않고 (None, [])다.

**검증 경계.** 이 예들은 존재, 부재, 빈 배열을 확인한다. 하지만 중복 값에서 어느 인덱스를 반환하는지, 정렬되지 않은 입력을 거부하는지, 매우 큰 배열에서도 같은 복잡도를 보이는지는 assert하지 않는다. 함수는 정렬 여부를 검사하지 않으므로 호출자가 계약을 지켜야 한다. 중복이 있으면 발견한 위치 하나를 반환할 뿐 첫 위치를 보장하지 않는다.

시간은 후보를 절반씩 줄이므로 O(log n), trace에도 반복마다 한 튜플을 넣으므로 추가 공간은 O(log n)이다. trace를 없애면 검색 상태 자체는 상수 개 변수라 O(1) 추가 공간이다.

## 2. 안정 병합과 병합 정렬 모델

레코드는 (키, 이름) 튜플이다. **안정성**은 키가 같은 레코드의 입력 순서가 출력에서도 유지되는 성질이다. (3,"A")가 (3,"C")보다 먼저 들어오면 정렬 뒤에도 A가 C 앞에 있어야 한다.

stable_merge는 이미 키 순서로 정렬된 left와 right 두 목록을 합친다.

~~~python
def stable_merge(left, right):
    merged = []
    i = j = 0
    while i < len(left) and j < len(right):
        if left[i][0] <= right[j][0]:
            merged.append(left[i])
            i += 1
        else:
            merged.append(right[j])
            j += 1
    merged.extend(left[i:])
    merged.extend(right[j:])
    return merged
~~~

i와 j는 아직 출력하지 않은 첫 레코드 위치다. 비교에 <=를 써서 키가 같을 때 left를 먼저 꺼낸다. 원래 배열의 왼쪽 절반 레코드는 오른쪽 절반보다 앞에 있었으므로 이 선택이 안정성을 지킨다. 한쪽을 다 쓰면 다른 쪽의 남은 꼬리는 이미 정렬되어 있어 그대로 붙인다.

merge_sort는 길이 0 또는 1이면 그대로 복사해 반환한다. 그보다 길면 가운데에서 나누고, 두 절반을 재귀 호출로 정렬한 뒤 stable_merge로 합친다.

입력 [(3,"A"),(1,"B"),(3,"C"),(2,"D")]의 전체 분할과 결합은 다음과 같다.

1. 네 레코드를 왼쪽 [(3,A),(1,B)]와 오른쪽 [(3,C),(2,D)]로 나눈다.
2. 왼쪽을 [(3,A)]와 [(1,B)]로 나눈다. 두 길이 1 목록은 그대로 돌아온다.
3. 키 3과 1을 비교해 B를 먼저 꺼내고 남은 A를 붙여 [(1,B),(3,A)]를 만든다.
4. 오른쪽을 [(3,C)]와 [(2,D)]로 나누고, D 뒤에 C를 붙여 [(2,D),(3,C)]를 만든다.
5. 최종 병합에서 B의 1과 D의 2를 비교해 B, A의 3과 D의 2를 비교해 D를 꺼낸다.
6. A의 3과 C의 3이 같다. <= 때문에 왼쪽 A를 먼저 꺼낸 뒤 C를 붙인다.
7. 출력은 [(1,B),(2,D),(3,A),(3,C)]다.

마지막 같은 키 비교에서 <를 사용했다면 C가 A보다 먼저 나와 안정성이 깨진다. 코드의 assert는 전체 예상 배열과 같음을 확인하므로 이 입력에서는 안정성 회귀도 잡는다.

시간은 각 병합 층에서 n개 레코드를 한 번씩 옮기고 층이 log₂n개이므로 O(n log n)이다. 병합 결과와 잘라 낸 목록이 필요하므로 추가 공간은 O(n) 규모다. assert 하나는 네 레코드 사례를 확인할 뿐 모든 길이와 모든 중복 배치를 증명하지 않는다. 일반 정확성은 “각 재귀 결과가 정렬되어 있다”는 가정과 병합 불변식으로 따로 설명해야 한다.

## 3. BFS: 큐와 방문 집합의 상태

그래프 입력은 딕셔너리다. 키는 정점이고 값 목록은 그 정점에서 바로 갈 수 있는 이웃이다.

~~~python
graph = {
    "A": ["B", "C"],
    "B": ["D"],
    "C": ["D"],
    "D": [],
}
~~~

BFS는 deque라는 양끝 큐를 쓴다. 큐는 먼저 넣은 정점을 먼저 꺼낸다. visited는 이미 발견한 정점의 집합이고, order는 실제 처리 순서다. 시작 A를 큐에 넣을 때 바로 visited에도 넣는다.

| 단계 | 꺼낸 정점 | 큐: 꺼내기 전 | 새로 넣은 이웃 | visited 뒤 | order 뒤 |
|---:|---|---|---|---|---|
| 시작 | - | [A] | - | {A} | [] |
| 1 | A | [A] | B,C | {A,B,C} | [A] |
| 2 | B | [B,C] | D | {A,B,C,D} | [A,B] |
| 3 | C | [C,D] | 없음: D는 방문됨 | 그대로 | [A,B,C] |
| 4 | D | [D] | 없음 | 그대로 | [A,B,C,D] |

출력은 ["A","B","C","D"]다. D는 B와 C 양쪽에서 보이지만 B를 처리할 때 visited에 넣었으므로 한 번만 큐에 들어간다. 방문 표시를 꺼낼 때까지 미루면 D가 두 번 큐에 들어갈 수 있다. 최종 출력에서 중복을 걸러도 큐 메모리와 간선 처리가 불필요하게 늘어난다.

assert는 이 그래프와 이웃 순서에서 정확한 order를 검사한다. 이웃 목록의 순서를 C,B로 바꾸면 같은 거리 층을 방문하면서 order는 A,C,B,D가 될 수 있다. BFS가 보장하는 핵심은 무가중 그래프에서 시작점으로부터 간선 수가 작은 층부터 처리한다는 것이지 같은 층의 유일한 순서는 아니다.

## 4. DFS: 스택과 역순 삽입

DFS는 목록을 스택으로 사용한다. 스택은 마지막에 넣은 정점을 먼저 꺼낸다. visited는 꺼낸 뒤 검사하며, 이미 방문했으면 건너뛴다. 현재 코드가 이웃을 reversed로 뒤집어 넣는 이유는 원래 이웃 목록의 첫 항목을 다음에 먼저 꺼내기 위해서다.

| 단계 | pop 전 stack | pop | 방문 뒤 order | 이웃 역순 push 뒤 stack |
|---:|---|---|---|---|
| 시작 | [A] | - | [] | [A] |
| 1 | [A] | A | [A] | [C,B] |
| 2 | [C,B] | B | [A,B] | [C,D] |
| 3 | [C,D] | D | [A,B,D] | [C] |
| 4 | [C] | C | [A,B,D,C] | [D] |
| 5 | [D] | D | 이미 방문, 변화 없음 | [] |

출력은 ["A","B","D","C"]다. C를 처리할 때 D를 스택에 넣지만 D는 이미 방문했다. 다음 pop에서 건너뛴다. 방문을 push 시점에 표시하는 다른 올바른 구현도 가능하며 그때 중복 push를 줄일 수 있다. 현재 모델의 상태 변화와 섞어 해석하면 안 된다.

assert는 한 그래프와 이웃 순서만 검사한다. 깊은 경로에서 재귀 한계를 피하는 반복형 스택이라는 점은 확인할 수 있지만, 연결되지 않은 모든 정점을 자동으로 순회하지는 않는다. 시작 A에서 닿지 않는 E는 출력에 없다.

## 5. 다익스트라: 거리 표와 우선순위 큐

가중 그래프는 이웃과 이동 비용 쌍을 저장한다.

~~~python
weighted = {
    "A": [("B", 4), ("C", 1)],
    "B": [("D", 1)],
    "C": [("B", 2), ("D", 5)],
    "D": [],
}
~~~

dist는 현재까지 발견한 최단 거리 상한이다. 처음 A는 0, 나머지는 무한대다. 최소 힙에는 (거리, 정점)을 넣어 가장 작은 거리 후보를 먼저 꺼낸다. **완화**는 현재 정점을 거쳐 이웃으로 가는 새 거리 distance+weight가 기존 dist[neighbor]보다 작으면 거리 값을 낮추는 연산이다.

| pop | 꺼낸 항목 | 완화 결과 | dist A,B,C,D | push 뒤 핵심 heap |
|---:|---|---|---|---|
| 시작 | - | - | 0,∞,∞,∞ | (0,A) |
| 1 | (0,A) | B=4, C=1 | 0,4,1,∞ | (1,C),(4,B) |
| 2 | (1,C) | B=3, D=6 | 0,3,1,6 | (3,B),(4,B),(6,D) |
| 3 | (3,B) | D=4 | 0,3,1,4 | (4,B),(6,D),(4,D) |
| 4 | (4,B) | 오래된 항목이라 건너뜀 | 그대로 | (4,D),(6,D) |
| 5 | (4,D) | 이웃 없음 | 그대로 | (6,D) |
| 6 | (6,D) | 오래된 항목이라 건너뜀 | 그대로 | 빈 힙 |

힙 안의 (4,B)는 B의 거리가 3으로 줄기 전에 넣은 오래된 항목이다. 코드의 distance != dist[node] 검사가 이를 건너뛴다. 출력 dist는 {"A":0,"B":3,"C":1,"D":4}다. A-C-B-D 경로 비용 1+2+1=4가 D까지 최단이다.

함수는 시작 전에 모든 간선을 훑어 음수 가중치가 있으면 ValueError를 낸다. A->B 비용 -1인 입력에 대해 assert는 이 예외가 발생하는지 확인한다. 음수 간선에서 다익스트라의 “가장 작은 후보를 먼저 확정해도 된다”는 근거가 깨지므로 조용히 틀린 값을 내는 대신 계약 위반을 드러낸다.

이 모델은 거리만 반환하고 부모 정점을 저장하지 않으므로 실제 경로는 복원하지 못한다. 연결되지 않은 정점은 무한대로 남는다. 음수 간선 거부 assert는 중요한 경계를 확인하지만, 큰 그래프의 시간 O((V+E)log V)나 모든 비음수 그래프의 정확성을 증명하지 않는다.

## 6. 최소 동전 DP와 탐욕 반례

min_coin_table(6,[1,3,4])은 금액 0부터 6까지 필요한 최소 동전 수를 표로 만든다. dp[x]는 금액 x의 답이라는 상태 정의다. dp[0]=0은 동전을 하나도 쓰지 않아 금액 0을 만드는 기본값이다.

| x | 가능한 마지막 동전 | 후보 수 | dp[x] |
|---:|---|---|---:|
| 0 | 없음 | 기본값 | 0 |
| 1 | 1 | dp[0]+1=1 | 1 |
| 2 | 1 | dp[1]+1=2 | 2 |
| 3 | 1,3 | 3,1 | 1 |
| 4 | 1,3,4 | 2,2,1 | 1 |
| 5 | 1,3,4 | 2,3,2 | 2 |
| 6 | 1,3,4 | 3,2,3 | 2 |

출력은 [0,1,2,1,1,2,2]이고 dp[6]=2는 3+3을 뜻한다. 현재 함수는 최소 개수만 저장하므로 동전 조합을 직접 반환하지 않는다. 조합을 복원하려면 각 x에서 선택한 마지막 동전을 별도 배열에 기록해야 한다.

greedy_coin_count는 남은 금액 이하의 가장 큰 동전을 계속 고른다. 6에서 4를 고르면 남은 값 2, 이어 1과 1을 골라 총 3개다. DP의 2개보다 나쁘다. assert는 dp[6]==2와 greedy 결과 3을 함께 검사해 동전 [1,3,4]에서 탐욕 규칙이 최적이 아님을 보여 준다.

DP 시간은 금액 1..A마다 k개 동전을 보므로 O(kA), 공간은 A+1칸이라 O(A)다. 이는 A 값에 비례하는 의사다항 비용이다. 동전 1이 없고 만들 수 없는 금액이 있으면 무한대 상태가 남을 수 있다. 현재 assert는 그런 경우나 0·음수 동전 입력을 검사하지 않는다.

## 7. 0/1 배낭의 역방향 갱신

입력 용량은 5, 물건은 [(2,3),(3,4)]다. 각 쌍은 (무게, 가치)다. 0/1은 각 물건을 최대 한 번만 쓸 수 있다는 뜻이다. dp[c]는 지금까지 본 물건만 사용해 용량 c 이내에서 얻는 최대 가치다.

첫 물건 (2,3)을 처리할 때 c를 5부터 2까지 내림차순으로 갱신한다.

| 상태 | c=0 | 1 | 2 | 3 | 4 | 5 |
|---|---:|---:|---:|---:|---:|---:|
| 시작 | 0 | 0 | 0 | 0 | 0 | 0 |
| (2,3) 뒤 | 0 | 0 | 3 | 3 | 3 | 3 |
| (3,4) 뒤 | 0 | 0 | 3 | 4 | 4 | 7 |

두 번째 물건에서 c=5 후보는 이전 dp[2]+4=7이라 두 물건을 함께 고른다. 출력은 7이고 assert가 이를 확인한다.

용량을 작은 쪽에서 큰 쪽으로 갱신하면 같은 물건으로 방금 바꾼 dp[c-weight]를 다시 읽을 수 있다. 첫 물건에서 dp[2]=3 뒤 dp[4]=dp[2]+3=6이 되어 무게 2 물건을 두 번 쓴 결과가 된다. 역방향은 현재 물건을 처리하기 전 상태만 참조하게 하여 0/1 계약을 지킨다.

시간은 물건 n개마다 최대 W칸을 보므로 O(nW), 공간은 W+1칸이라 O(W)다. assert는 두 물건 조합을 확인하지만 무게 0, 음수 가치, 빈 목록, 최적 조합 복원은 검사하지 않는다.

## 8. assert가 확인하는 정확한 범위

두 파일의 작은 검사는 다음 사실을 확인한다.

| 함수 | 확인한 입력 | 확인한 출력·실패 |
|---|---|---|
| binary_search | 존재 44, 부재 43, 빈 배열 | 위치와 정확한 trace |
| merge_sort | 중복 키가 있는 네 레코드 | 정렬 순서와 A-before-C 안정성 |
| bfs | 네 정점 합류 그래프 | A,B,C,D |
| dfs | 같은 그래프 | A,B,D,C |
| dijkstra | 비음수 네 정점 그래프 | 거리 0,3,1,4 |
| dijkstra | 음수 간선 하나 | ValueError |
| min_coin_table | 동전 1,3,4와 금액 6 | 전체 표와 최솟값 2 |
| greedy_coin_count | 같은 동전과 금액 | 3이라는 반례 |
| knapsack_01 | 용량 5, 두 물건 | 최대 가치 7 |

search_sort_lab.py는 검사가 끝나면 “search_sort_lab: 선택한 정확성 예제가 통과했습니다”를 출력하도록 작성되어 있다. graph_dp_lab.py도 “graph_dp_lab: 선택한 정확성 예제가 통과했습니다”를 출력한다. 이 문장은 파일 안의 assert가 실패하지 않았다는 뜻이다. 모든 가능한 입력을 검사했다거나 복잡도 상한을 측정했다는 뜻은 아니다.

## 9. 완전 풀이 1: 이진 검색 마지막 칸

**문제.** keys=[2,5,9], target=9의 상태와 lo<=hi가 필요한 이유를 보이라.

**풀이.** 시작 (lo,mid,hi)=(0,1,2), 값 5가 작아 lo=2가 된다. 이제 (2,2,2) 한 칸이 남는다. lo<hi를 썼다면 2<2가 거짓이라 9를 검사하지 못한다. lo<=hi이면 keys[2]=9를 확인해 인덱스 2를 반환한다. 닫힌 구간이라는 구현 선택과 반복 조건이 맞아야 한다.

**변경 조건.** hi를 len(keys)로 두는 반열린 구간 구현은 조건과 갱신식이 달라진다. 두 규칙을 섞으면 범위를 벗어나거나 마지막 칸을 놓친다.

## 10. 완전 풀이 2: 안정성 한 글자

**문제.** 병합 비교의 <=를 <로 바꾸면 [(2,A),(2,B)]는 어떻게 되는가?

**풀이.** 분할 뒤 left=[(2,A)], right=[(2,B)]다. 2<2는 거짓이므로 오른쪽 B를 먼저 꺼내고 A를 붙여 [(2,B),(2,A)]가 된다. 키 순서는 맞지만 입력의 동률 순서가 뒤집혀 불안정하다.

**변경 조건.** 레코드가 숫자뿐이고 같은 값끼리 구분할 정보가 없다면 관찰하기 어렵다. 가입 순서처럼 보조 의미가 있으면 안정성이 제품 동작을 바꾼다.

## 11. 완전 풀이 3: BFS 방문 표시 시점

**문제.** D를 큐에서 꺼낼 때 방문 표시하면 위 그래프에서 무슨 일이 생기는가?

**풀이.** B가 D를 넣은 뒤에도 D는 미방문이다. 다음 C도 D를 넣어 큐가 [D,D]가 된다. 첫 D를 처리한 뒤 둘째 D를 건너뛸 수는 있지만 큐 삽입과 pop이 늘었다. 넣는 순간 표시하면 최초 발견 한 번만 큐에 들어간다.

**변경 조건.** 경로별 상태가 달라 같은 정점을 여러 번 방문해야 하는 탐색이라면 단순 정점 visited가 계약에 맞지 않는다. 상태를 (정점,열쇠 보유 여부)처럼 확장해야 한다.

## 12. 완전 풀이 4: DFS의 reversed

**문제.** reversed를 제거하면 첫 두 방문은 어떻게 바뀌는가?

**풀이.** A의 이웃 B,C를 그대로 extend하면 stack=[B,C]다. 스택은 끝 C를 먼저 꺼내므로 방문은 A,C로 시작한다. reversed하면 [C,B]가 되어 B가 먼저 나온다. 두 결과 모두 DFS가 될 수 있지만 코드의 정확한 출력 assert는 이웃 순서를 포함한 구현 계약을 검사한다.

**변경 조건.** 방문 순서가 제품 결과와 무관하면 집합으로 검증할 수 있다. 사전식 순서가 필요하면 이웃 정렬 비용까지 포함해야 한다.

## 13. 완전 풀이 5: 오래된 힙 항목

**문제.** 다익스트라의 (4,B)를 처리해도 답이 틀리는가?

**풀이.** 비음수 간선에서는 현재 dist[B]=3보다 큰 오래된 거리 4로 완화를 시도해도 더 좋은 후보를 만들지 못해 보통 답은 유지된다. 그러나 쓸모없는 간선을 다시 훑는다. distance != dist[node] 검사는 오래된 항목을 빠르게 버려 효율을 지킨다.

**변경 조건.** 방문 확정 집합을 쓰는 구현에서는 정점을 최초 최소 거리 pop 때 확정한다. 자료구조와 중복 처리 규칙을 함께 설명해야 한다.

## 14. 완전 풀이 6: 동전 조합 복원

**문제.** dp[6]=2만으로 3+3을 어떻게 복원하는가?

**풀이.** 각 x에서 최솟값을 만든 동전을 choice[x]에 기록한다. x=6에서 choice[6]=3, 남은 x=3이다. choice[3]=3을 읽으면 남은 값 0이라 종료한다. 결과 [3,3]의 합은 6이고 길이는 dp[6]=2다.

**변경 조건.** 1+5처럼 최적 조합이 여러 개면 순회하는 동전 순서나 동률 규칙이 반환 조합을 정한다. 최소 개수만 같다는 것과 특정 조합까지 같다는 것을 구분해 assert한다.

## 15. 완전 풀이 7: 배낭 정방향 반례

**문제.** 첫 물건 (2,3)을 정방향으로 갱신한 표를 보이라.

**풀이.** c=2에서 dp[2]=3이다. c=3도 3이다. c=4에서는 방금 갱신한 dp[2]+3=6이 된다. 이는 같은 물건 두 개를 쓴 값이다. c=5도 dp[3]+3=6이다. 0/1 계약을 어겼다. 역방향이면 c=4를 계산할 때 이전 단계 dp[2]=0을 읽어 3만 저장한다.

**변경 조건.** 동전을 무제한 사용할 수 있는 완전 배낭 문제라면 정방향 갱신이 의도한 동작이다. 반복 방향은 작은 구현 취향이 아니라 문제 계약을 코드로 옮긴 결과다.

## 16. 완전 풀이 8: assert와 증명

**문제.** 모든 제공 assert가 통과하면 이진 검색이 모든 정렬 배열에서 맞다고 결론 내려도 되는가?

**풀이.** 안 된다. assert는 선택한 세 입력에서 관측한 사실이다. 일반 정확성에는 반복 시작마다 target이 있다면 닫힌 후보 구간 lo..hi 안에 있다는 불변식을 세운다. 비교 뒤 버린 절반에는 target이 없음을 정렬성으로 보이고, 구간이 줄어 종료함을 보인다. 종료 시 빈 구간이면 target이 없고, 같음을 발견하면 반환 인덱스가 맞다.

**변경 조건.** 속성 기반 테스트로 많은 무작위 배열을 검사하면 반례 발견 능력은 커지지만 여전히 유한한 테스트다. 증명과 테스트는 서로 다른 종류의 근거로 함께 둔다.

## 17. 실습 검증 체크리스트

- 함수가 받는 입력 객체와 반환 객체를 한 문장으로 썼는가?
- 상태 변수 각각이 무엇을 의미하는지 반복 전후로 유지되는가?
- 표의 한 행을 실제 코드 한 반복과 연결했는가?
- assert가 확인하는 값과 확인하지 않는 경계를 구분했는가?
- 오류 입력이 예외, None, 무한대 중 무엇으로 표현되는가?
- 시간·공간 계산에 trace나 복원 배열 같은 진단 상태도 포함했는가?
- 이웃 순서, 동률 규칙, 갱신 방향처럼 출력에 영향을 주는 구현 선택을 기록했는가?

작은 로컬 모델의 목적은 큰 시스템을 흉내 내는 것이 아니다. 입력 하나가 어느 변수와 자료구조를 거쳐 어떤 출력이 되는지 눈으로 확인하고, 예상과 다른 첫 상태에서 오류를 멈추는 것이다. 그 추적 위에 불변식과 비용 계산을 얹으면 assert가 보여 주는 사례와 일반적인 주장 사이의 경계도 선명해진다.
