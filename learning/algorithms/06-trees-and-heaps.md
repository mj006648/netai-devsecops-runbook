# 06. 트리와 힙

[이전](05-sorting.md) · [목차](README.md) · [다음](07-graphs-and-traversal.md)

트리는 하나의 대상 아래에 다른 대상들이 갈라지는 계층을 표현한다. 파일 시스템의 폴더, 조직도, 검색 범위가 절반씩 줄어드는 구조가 예다. 힙은 트리 모양을 이용하지만 모든 값을 정렬하지 않고 가장 작은 값이나 가장 큰 값 하나를 빠르게 꺼내는 데 집중한다.

~~~mermaid
flowchart TD
    8 --> 3
    8 --> 12
    3 --> 1
    3 --> 6
    12 --> 10
    12 --> 14
~~~

## 1. 트리를 이루는 실제 객체와 관계

**노드(node)**는 트리에 저장되는 객체 하나다. 검색 트리 노드라면 키, 연결할 노드의 위치, 필요하면 부가 데이터를 메모리에 가진다. **간선(edge)**은 두 노드의 연결 관계다. 포인터 기반 구현에서는 한 노드가 다른 노드의 메모리 위치를 참조하는 필드가 간선을 만든다.

트리에서 위 노드를 **부모(parent)**, 그 바로 아래 연결된 노드를 **자식(child)**이라 한다. 부모가 없는 시작 노드는 **루트(root)**다. 자식이 없는 노드는 **잎(leaf)**이다. 한 노드 아래에 이어지는 모든 노드와 간선을 그 노드의 **부분 트리(subtree)**라고 한다.

노드를 간선 따라 잇는 순서를 **경로(path)**라고 한다. 노드의 **깊이(depth)**는 루트에서 그 노드까지 지나가는 간선 수다. 루트 깊이는 0이고 그림의 6은 8→3→6 두 간선을 지나므로 깊이 2다. 노드의 **높이(height)**는 그 노드에서 아래 잎까지 가장 긴 경로의 간선 수다. 잎의 높이는 0이고 전체 트리의 높이는 루트 높이다. 그림은 루트에서 잎까지 두 간선이므로 높이 2다.

각 노드가 자식을 최대 두 개 가지면 **이진 트리(binary tree)**다. 두 자리는 왼쪽 자식과 오른쪽 자식으로 구분한다. 트리는 값의 중복 연결이나 순환이 없는 계층이라는 전제를 둔다. 한 자식이 부모 둘을 갖거나 아래로 내려가 다시 자신에게 돌아오면 이 장에서 말하는 트리가 아니다.

~~~python
class Node:
    def __init__(self, key):
        self.key = key
        self.left = None
        self.right = None
~~~

각 Node 객체는 비교할 key와 왼쪽·오른쪽 자식 객체를 가리키는 필드를 가진다. None은 그 방향에 자식이 없다는 뜻이다. 실제 메모리에서 노드가 그림처럼 붙어 있을 필요는 없다. 참조가 논리적 연결을 만든다.

## 2. 이진 검색 트리의 순서 규칙

**이진 검색 트리(BST, Binary Search Tree)**는 각 노드에서 왼쪽 부분 트리의 모든 키가 노드 키보다 작고, 오른쪽 부분 트리의 모든 키가 노드 키보다 크다는 불변식을 가진 이진 트리다. 불변식은 모든 정상 연산 전후에 계속 참이어야 하는 조건이다.

이 장은 중복 키를 저장하지 않고, 같은 키를 삽입하면 기존 노드를 그대로 반환하는 정책을 쓴다. 중복을 오른쪽에 놓거나 노드에 개수를 저장하는 정책도 가능하지만 검색·삭제 코드가 그 정책과 일치해야 한다.

그림의 트리를 집합 표기로 쓰면 다음과 같다.

~~~text
        8
      /   \
     3     12
    / \    / \
   1   6  10 14
~~~

8의 왼쪽 값 1, 3, 6은 모두 8보다 작고 오른쪽 10, 12, 14는 모두 크다. 3과 12를 루트로 보는 각 부분 트리에서도 같은 규칙이 반복된다.

## 3. 검색의 전체 추적과 정확성

target 7을 찾는 과정을 보자.

| 단계 | 현재 노드 | 비교 | 버린 부분 트리 | 다음 위치 |
| ---: | ---: | --- | --- | --- |
| 1 | 8 | 7 < 8 | 8의 오른쪽 전체 | 왼쪽 3 |
| 2 | 3 | 7 > 3 | 3의 왼쪽 전체 | 오른쪽 6 |
| 3 | 6 | 7 > 6 | 6의 왼쪽 전체 | 오른쪽 None |
| 4 | 없음 | 후보가 비었음 | 없음 | 부재 반환 |

검색 불변식은 “target이 트리에 있다면 현재 노드를 루트로 하는 부분 트리 안에 있다”이다. 7이 8보다 작으면 BST 규칙상 8의 오른쪽에는 있을 수 없다. 같은 논리로 한쪽을 버려도 후보를 잃지 않는다. None에 도달하면 후보 부분 트리가 비었으므로 target이 없다.

~~~python
def search(root, target):
    current = root
    while current is not None:
        if target == current.key:
            return current
        if target < current.key:
            current = current.left
        else:
            current = current.right
    return None
~~~

current는 현재 후보 부분 트리의 루트다. 같으면 실제 Node 객체를 반환한다. 작으면 왼쪽, 크면 오른쪽 참조를 따라간다. 연결 하나를 따라갈 때마다 깊이가 1 늘어나므로 시간은 트리 높이 h에 비례하는 O(h)다. 추가 변수 하나만 써 공간은 O(1)이다.

**균형(balance)**은 왼쪽과 오른쪽 부분 트리 높이가 심하게 치우치지 않도록 관리된 상태를 뜻한다. 노드 n개의 균형 트리 높이는 O(log n)이라 검색도 O(log n)이다. 그러나 1,2,3,4를 차례로 평범한 BST에 넣으면 오른쪽으로만 연결된 높이 3의 사슬이 된다. 일반적으로 높이가 n-1까지 커져 검색 O(n)이 될 수 있다. “BST 검색은 항상 O(log n)”이라는 말에는 균형 조건이 빠져 있다.

## 4. 삽입: 빈 자리를 찾고 연결하기

삽입은 실패한 검색이 끝난 None 자리에 새 노드를 연결한다.

~~~python
def insert(root, key):
    if root is None:
        return Node(key)

    current = root
    while True:
        if key == current.key:
            return root

        if key < current.key:
            if current.left is None:
                current.left = Node(key)
                return root
            current = current.left
        else:
            if current.right is None:
                current.right = Node(key)
                return root
            current = current.right
~~~

빈 트리면 새 노드가 루트가 된다. 그 외에는 같은 키면 중복 정책에 따라 바꾸지 않는다. 작으면 왼쪽 자리가 비었는지, 크면 오른쪽 자리가 비었는지 검사한다. 비어 있으면 새 Node 객체를 만들고 부모의 참조 필드에 저장한다.

7을 삽입하면 8에서 왼쪽, 3에서 오른쪽, 6에서 오른쪽으로 간다. 6.right가 None이므로 그 필드가 새 Node(7)를 가리키게 한다.

~~~text
        8
      /   \
     3     12
    / \    / \
   1   6  10 14
        \
         7
~~~

새 노드는 기존 두 노드 사이에 끼어들지 않고 잎으로 붙는다. 지나온 각 비교가 BST 규칙에 맞는 방향을 골랐으므로 전체 불변식이 유지된다. 시간은 검색과 같은 O(h)다.

## 5. 순회: 모든 노드를 어떤 순서로 볼 것인가

**순회(traversal)**는 트리의 모든 노드를 정한 순서로 한 번씩 방문하는 일이다.

- 전위 순회는 현재 노드, 왼쪽, 오른쪽 순서다.
- 중위 순회는 왼쪽, 현재 노드, 오른쪽 순서다.
- 후위 순회는 왼쪽, 오른쪽, 현재 노드 순서다.

원래 7개 노드 트리의 전위는 8,3,1,6,12,10,14다. 중위는 1,3,6,8,10,12,14이고, 후위는 1,6,3,10,14,12,8이다. BST 중위 순회가 정렬 순서를 만드는 이유는 왼쪽의 모든 키가 현재 키보다 작고 오른쪽의 모든 키가 크며, 두 부분 트리도 같은 규칙을 갖기 때문이다.

재귀 순회는 높이만큼 호출 프레임을 사용한다. 모든 노드를 한 번 방문하므로 시간 O(n), 추가 호출 공간 O(h)다. 사슬 트리에서는 h가 n에 가까워질 수 있다.

## 6. 삭제의 세 경우

키를 삭제할 때는 그 노드로 들어오던 부모의 참조도 고쳐야 한다.

1. 자식이 없으면 부모 참조를 None으로 바꾼다.
2. 자식이 하나면 부모가 삭제 노드 대신 그 자식을 가리키게 한다.
3. 자식이 둘이면 순서를 깨지 않는 대체 키가 필요하다.

세 번째에 쓰는 **중위 후속자(inorder successor)**는 중위 순회에서 삭제 노드 바로 다음에 오는, 더 큰 키 중 가장 작은 노드다. 삭제 노드의 오른쪽 부분 트리로 한 번 간 뒤 가능한 한 왼쪽으로 내려가면 찾는다. 후속자는 왼쪽 자식이 없으므로 그 자리에서 제거할 때는 1번 또는 2번 경우가 된다.

루트 8을 삭제하는 전체 과정을 보자.

| 단계 | 현재 위치 | 동작 | 이유 |
| ---: | --- | --- | --- |
| 1 | 키 8 | 자식 둘 확인 | 바로 연결을 끊을 수 없음 |
| 2 | 오른쪽 루트 12 | 후속자 탐색 시작 | 8보다 큰 영역 |
| 3 | 12의 왼쪽 10 | 더 왼쪽 없음 | 가장 작은 큰 키는 10 |
| 4 | 8의 키 자리 | 10을 복사 | 왼쪽보다 크고 오른쪽 나머지보다 작음 |
| 5 | 원래 10 노드 | 12.left를 10의 오른쪽 자식 None으로 변경 | 중복 10 제거 |
| 6 | 완료 | 루트 10, 오른쪽 12의 왼쪽 비어 있음 | BST 복구 |

~~~text
삭제 전                 삭제 후
    8                       10
  /   \                    /  \
 3     12                 3    12
/ \   /  \               / \     \
1  6 10  14             1   6     14
~~~

~~~python
def delete(root, key):
    if root is None:
        return None

    if key < root.key:
        root.left = delete(root.left, key)
        return root

    if key > root.key:
        root.right = delete(root.right, key)
        return root

    if root.left is None:
        return root.right
    if root.right is None:
        return root.left

    successor = root.right
    while successor.left is not None:
        successor = successor.left

    root.key = successor.key
    root.right = delete(root.right, successor.key)
    return root
~~~

첫 조건은 빈 부분 트리에서 끝낸다. 키가 작거나 크면 해당 자식 부분 트리의 삭제 결과를 다시 자식 참조에 저장한다. 이 대입이 중요하다. 자식이 없는 노드를 지우면 None이, 자식 하나면 그 자식이 돌아오기 때문이다. 키를 찾은 뒤 왼쪽이 없으면 오른쪽을, 오른쪽이 없으면 왼쪽을 돌려준다. 둘 다 있으면 후속자 키를 복사하고 오른쪽 부분 트리에서 원래 후속자를 삭제한다. 시간과 재귀 공간은 O(h)다.

레코드에 키 외의 데이터가 있다면 키만 복사해서는 안 된다. 전체 레코드 내용을 옮기거나 노드 연결 자체를 바꿔야 한다. 중복 정책이 있다면 후속자 삭제도 그 정책을 따라야 한다.

## 7. 균형과 회전

정렬된 키 1,2,3을 순서대로 넣으면 1의 오른쪽에 2, 2의 오른쪽에 3이 붙는다. 높이가 2라 작은 예에서는 괜찮지만 n개면 높이 n-1이 된다.

**회전(rotation)**은 BST의 중위 순서를 유지하면서 몇 개 노드의 부모·자식 연결을 바꾸는 국소 연산이다. 오른쪽으로 치우친 1→2→3에 왼쪽 회전을 적용하면 2가 위로, 1이 왼쪽, 3이 오른쪽이 된다.

~~~text
1                 2
 \               / \
  2     →       1   3
   \
    3
~~~

두 트리의 중위 순서는 모두 1,2,3이지만 높이는 2에서 1로 줄었다. AVL 트리나 레드-블랙 트리는 높이 또는 색 규칙을 저장하고 삽입·삭제 뒤 회전과 추가 조정을 수행해 높이를 O(log n)으로 제한한다. 회전 한 번만 모든 트리를 자동으로 균형 있게 만드는 것은 아니다. 어떤 회전과 재색칠이 필요한지는 선택한 균형 트리의 불변식에 달려 있다.

## 8. 힙과 완전 이진 트리

**완전 이진 트리(complete binary tree)**는 마지막 깊이를 제외한 모든 깊이가 가득 차고, 마지막 깊이의 노드가 왼쪽부터 빈틈없이 채워진 이진 트리다. 이 모양이면 포인터 없이 배열에 연속으로 저장할 수 있다.

**최소 힙(min-heap)**은 완전 이진 트리이면서 모든 부모 키가 자식 키보다 작거나 같은 구조다. **힙(heap)**이라는 말은 여기서 이 모양 조건과 부모-자식 순서 조건을 함께 가리킨다. 형제끼리와 서로 다른 부분 트리 사이의 순서는 정하지 않는다.

0부터 시작하는 배열에서 인덱스 i의 왼쪽 자식은 2i+1, 오른쪽 자식은 2i+2다. i가 0보다 클 때 부모는 (i-1)//2다.

~~~text
배열: [2, 5, 4, 9, 7, 8]
인덱스 0의 값 2 → 자식 인덱스 1의 5, 2의 4
인덱스 1의 값 5 → 자식 인덱스 3의 9, 4의 7
인덱스 2의 값 4 → 자식 인덱스 5의 8
~~~

모든 쌍에서 부모가 자식보다 작거나 같으므로 올바른 최소 힙이다. 배열 자체는 2,4,5 순서로 정렬되지 않았다. 5가 4보다 앞에 있어도 둘은 형제라 힙 조건이 비교하지 않는다.

## 9. 힙 삽입의 배열 인덱스 전체 추적

새 값은 완전 이진 트리 모양을 지키기 위해 배열 끝, 즉 마지막 깊이의 왼쪽부터 비어 있는 자리에 넣는다. 그 뒤 부모보다 작으면 위로 교환하는 **위로 올리기(sift-up)**를 한다.

초기 힙 [2,5,4,9,7,8]에 3을 넣자.

| 단계 | 배열 | 현재 인덱스 | 부모 인덱스와 값 | 판단 |
| ---: | --- | ---: | --- | --- |
| 1 | [2,5,4,9,7,8,3] | 6 | (6-1)//2 = 2, 값 4 | 3 < 4, 교환 |
| 2 | [2,5,3,9,7,8,4] | 2 | (2-1)//2 = 0, 값 2 | 3 ≥ 2, 종료 |

3이 올라간 경로 외의 부모-자식 쌍은 바뀌지 않아 여전히 조건을 만족한다. 경로에서도 마지막 비교 뒤 2 ≤ 3이고, 3의 자식 8과 4보다 작다. 완전 트리 높이만큼 올라가므로 O(log n) 시간이다.

~~~python
def heappush(heap, value):
    heap.append(value)
    index = len(heap) - 1

    while index > 0:
        parent = (index - 1) // 2
        if heap[parent] <= heap[index]:
            break
        heap[parent], heap[index] = heap[index], heap[parent]
        index = parent
~~~

append는 새 잎 자리를 만든다. index는 그 칸 번호다. 루트가 아니면 부모를 계산하고, 부모가 이미 작으면 끝낸다. 그렇지 않으면 교환하고 현재 인덱스를 부모 위치로 바꿔 반복한다.

## 10. 최솟값 꺼내기의 전체 추적

최소 힙의 루트는 모든 자식보다 작고, 그 자식들도 자기 아래보다 작으므로 전체 최솟값이다. 루트만 지우면 0번에 구멍이 생긴다. 완전 모양을 유지하려고 마지막 값을 루트로 옮기고, 더 작은 자식과 교환하며 아래로 내리는 **아래로 내리기(sift-down)**를 한다.

힙 [2,5,3,9,7,8,4]에서 최솟값을 꺼내자.

| 단계 | 배열 | 현재 인덱스 | 자식 | 동작 |
| ---: | --- | ---: | --- | --- |
| 1 | [4,5,3,9,7,8] | 0 | 1번 5, 2번 3 | 작은 자식 3과 교환 |
| 2 | [3,5,4,9,7,8] | 2 | 5번 8, 오른쪽 없음 | 4 ≤ 8, 종료 |
| 결과 | [3,5,4,9,7,8] | 없음 | 없음 | 반환값 2 |

~~~python
def heappop(heap):
    if not heap:
        raise IndexError("heap is empty")

    smallest = heap[0]
    last = heap.pop()
    if not heap:
        return smallest

    heap[0] = last
    index = 0

    while True:
        left = 2 * index + 1
        right = left + 1
        if left >= len(heap):
            break

        smaller_child = left
        if right < len(heap) and heap[right] < heap[left]:
            smaller_child = right

        if heap[index] <= heap[smaller_child]:
            break

        heap[index], heap[smaller_child] = heap[smaller_child], heap[index]
        index = smaller_child

    return smallest
~~~

빈 힙 꺼내기는 저장된 값이 없어 오류다. pop으로 마지막 값을 제거하되, 원소가 하나뿐이었다면 저장한 최솟값을 바로 반환한다. 자식이 있으면 오른쪽 존재 여부를 검사하고 두 자식 중 작은 쪽을 고른다. 큰 자식과 바꾸면 작은 자식이 부모보다 작은 채 남으므로 반드시 작은 자식과 비교해야 한다. 이동은 높이만큼이라 O(log n)이고, 최솟값 읽기만 하면 heap[0]을 보므로 O(1)이다.

## 11. 우선순위 큐

**우선순위 큐(priority queue)**는 들어온 시간보다 우선순위 값을 기준으로 다음 항목을 꺼내는 추상적 동작 규칙이다. 일반 FIFO 큐는 먼저 들어온 항목을 꺼내지만, 최소 우선순위 큐는 priority가 가장 작은 항목을 꺼낸다. 힙은 이를 구현하는 대표 자료구조다.

항목을 (priority, sequence, item)처럼 저장할 수 있다. priority가 같을 때 먼저 들어온 항목을 원하면 계속 증가하는 sequence를 두 번째 비교 기준으로 쓴다. 힙 자체는 같은 우선순위의 입력 순서를 보장하지 않는다.

삽입과 최솟값 꺼내기는 O(log n), 최솟값 확인은 O(1)이다. 그러나 임의 키 7을 찾는 일은 루트에서 한 방향을 고를 수 없다. 부모보다 큰 값이 양쪽 어디에도 있을 수 있어 최악 O(n)이다. 힙 배열에 이진 검색을 적용할 수 없는 이유다.

## 12. 힙 만들기와 복잡도

빈 힙에 n개를 하나씩 넣으면 각 삽입 O(log n)으로 O(n log n) 상한을 얻는다. 더 빠른 **힙 만들기(build-heap)**는 완전 트리 배열의 마지막 내부 노드부터 루트 방향으로 각 노드를 sift-down한다. 잎은 이미 자식 조건을 만족한다.

시간은 O(n)이다. 높이가 큰 루트 부근 노드는 적고, 대부분 노드는 아래쪽에 있어 한두 단계만 이동한다. 모든 노드가 log n만큼 움직인다고 곱하면 실제 구조보다 느슨한 O(n log n) 상한만 얻는다. 각 높이의 노드 수와 이동 거리를 합하면 선형으로 제한된다.

힙 공간은 n개 값을 배열 n칸에 저장한다. 인덱스 계산으로 간선을 표현하므로 자식 포인터가 필요 없다. 배열의 연속 저장은 메모리에서 가까운 값을 읽는 데 유리할 수 있다. 반면 BST는 각 Node 객체와 자식 참조, 균형 트리라면 높이·색 같은 메타데이터도 저장한다.

## 13. 확인 문제와 자세한 풀이

### 문제 1. 깊이와 높이

원래 7개 노드 트리에서 10의 깊이, 노드 12의 높이, 전체 높이를 구하라. 14 아래에 16을 붙이면 무엇이 바뀌는가?

**풀이.** 10은 8→12→10의 간선 두 개를 지나 깊이 2다. 12에서 잎 10 또는 14까지 한 간선이므로 12의 높이는 1이다. 루트 8에서 잎까지 가장 긴 경로가 두 간선이라 전체 높이는 2다. 14의 오른쪽에 16을 붙이면 16의 깊이는 3, 14의 높이는 1, 12의 높이는 2, 전체 높이는 3으로 늘어난다. 다른 노드의 깊이는 변하지 않는다.

### 문제 2. BST 검색과 삽입

원래 트리에서 11을 검색한 경로와, 이어 11을 삽입할 위치를 구하라.

**풀이.** 11은 8보다 커 오른쪽 12로 간다. 12보다 작아 왼쪽 10으로 가고, 10보다 커 오른쪽을 본다. 10.right가 None이므로 검색은 부재로 끝난다. 삽입은 바로 그 None 자리에 Node(11)를 연결한다. 10 < 11 < 12이므로 12의 왼쪽 부분 트리 규칙과 10의 오른쪽 규칙을 모두 만족한다.

### 문제 3. 자식 하나 삭제

7을 삽입한 트리에서 6을 삭제하면 부모 3의 오른쪽 참조는 무엇을 가리켜야 하는가?

**풀이.** 6은 왼쪽 자식이 없고 오른쪽 자식 7 하나가 있다. 6 노드를 단순히 None으로 바꾸면 7까지 잃는다. 삭제 함수는 6 대신 그 오른쪽 자식 7을 반환하고, 호출한 부모 3은 root.right 결과를 자기 right에 저장한다. 따라서 3.right는 7을 가리킨다. 3 < 7 < 8이라 BST 순서도 유지된다.

### 문제 4. 두 자식 삭제와 후속자

원래 트리에서 3을 삭제할 때 중위 후속자는 무엇이며 최종 연결은 어떻게 되는가?

**풀이.** 3의 오른쪽 부분 트리 루트는 6이고 더 왼쪽 자식이 없으므로 후속자는 6이다. 3의 키 자리를 6으로 바꾸고 원래 6 노드를 오른쪽 부분 트리에서 삭제한다. 원래 6은 잎이므로 새 6 노드 자리의 오른쪽 참조는 None이 된다. 루트 8의 왼쪽은 키 6이고 그 왼쪽에 1이 남는다. 중위 순서는 1,6,8,10,12,14다.

### 문제 5. 회전의 의미

1→2→3 오른쪽 사슬을 왼쪽 회전한 뒤 중위 순서와 높이를 비교하라. 회전이 키를 정렬하는 연산인가?

**풀이.** 회전 전 중위 순서는 1,2,3이고 높이는 2다. 2를 위로 올리면 왼쪽 1, 오른쪽 3이 되어 중위 순서는 여전히 1,2,3이며 높이는 1이다. 회전은 키 값을 교환해 새 순서를 계산하는 정렬이 아니다. 같은 BST 중위 순서를 유지하면서 연결과 높이를 바꾸는 연산이다. 더 큰 트리에서는 관련 부분 트리 연결도 함께 옮겨야 한다.

### 문제 6. 힙 삽입

최소 힙 [1,4,2,9,7,8]에 0을 넣을 때 배열 상태와 인덱스를 모두 추적하라.

**풀이.** 끝 인덱스 6에 0을 붙여 [1,4,2,9,7,8,0]이 된다. 부모는 (6-1)//2 = 2이고 값 2라 교환해 [1,4,0,9,7,8,2], 현재 인덱스는 2다. 새 부모는 (2-1)//2 = 0이고 값 1이라 다시 교환해 [0,4,1,9,7,8,2]가 된다. 인덱스 0은 루트라 종료한다. 두 번 교환했고 높이에 비례한다.

### 문제 7. 힙과 정렬 배열의 차이

최소 힙 [1,5,3,9,7]에서 두 번째 최솟값은 어디에서 찾을 수 있으며, 값 7을 이진 검색할 수 없는 이유는 무엇인가?

**풀이.** 최솟값 1 다음 후보는 루트의 두 자식 5와 3 중 작은 3이므로 두 번째 최솟값은 인덱스 2다. 그러나 일반적인 k번째 값은 단순히 배열 k번째 칸이 아니다. 7은 부모 5보다 크다는 조건만 만족하면 여러 잎 위치에 올 수 있다. 힙 배열은 전체 오름차순이 아니므로 가운데 값과 비교해 절반을 버리는 이진 검색 논리가 성립하지 않는다. 임의 값 검색은 최악에 모든 노드를 봐 O(n)이다.

## 14. 구현 점검표

BST에서는 중복 정책, 각 노드의 왼쪽·오른쪽 전체 범위, 삭제 뒤 부모 참조 갱신을 확인한다. 성능을 말할 때 노드 수만 보지 말고 실제 높이와 균형 보장을 확인한다. 두 자식 삭제는 후속자 레코드 전체가 올바르게 이동하는지 검사한다.

힙에서는 완전 트리 모양과 부모-자식 부등식을 따로 확인한다. 삽입은 배열 끝에서 위로, 꺼내기는 마지막 값을 루트로 옮긴 뒤 작은 자식 쪽으로 내려간다. 빈 힙, 원소 하나, 같은 우선순위, 오른쪽 자식이 없는 마지막 내부 노드를 시험한다. 힙이 보장하는 것은 루트의 극값이지 배열 전체 정렬이 아니다.

## 참고

이 장은 중복 키를 저장하지 않는 BST와 0 기반 배열 최소 힙을 사용했다. 다른 중복 정책, 최대 힙, 균형 트리는 불변식과 비교 방향을 그 선택에 맞게 바꿔야 한다.
