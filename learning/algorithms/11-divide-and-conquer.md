# 11. 분할 정복

[이전](10-dynamic-programming.md) · [목차](README.md) · [다음](12-choosing-and-limitations.md)

분할 정복은 큰 입력을 직접 붙잡고 풀기보다 서로 분리된 작은 입력들로 나누고, 각 답을 구한 뒤 전체 답으로 합치는 설계 방식이다. 이름만 세 단계로 외우면 재귀가 끝나지 않거나 같은 원소를 두 번 처리하기 쉽다. 이 장은 실제 배열 구간, 호출 프레임, 단계별 비용이 어떻게 변하는지 끝까지 추적한다.

~~~mermaid
flowchart TD
    N["크기 8"] --> L["크기 4"]
    N --> R["크기 4"]
    L --> L1["크기 2"]
    L --> L2["크기 2"]
    R --> R1["크기 2"]
    R --> R2["크기 2"]
    L1 --> O1["크기 1 두 개"]
    L2 --> O2["크기 1 두 개"]
    R1 --> O3["크기 1 두 개"]
    R2 --> O4["크기 1 두 개"]
~~~

## 1. 세 단계와 메모리의 대상

**분할(divide)**은 입력 객체를 더 작은 부분 문제들의 입력 범위로 나누는 단계다. 배열을 실제로 복사할 수도 있고, lo와 hi 인덱스로 원래 배열의 구간만 가리킬 수도 있다. **정복(conquer)**은 각 부분 문제를 직접 풀거나 같은 함수를 재귀 호출해 푸는 단계다. **결합(combine)**은 부분 답 객체들을 전체 답 하나로 만드는 단계다.

**분할 정복(divide and conquer)**은 이 세 단계가 반복되는 알고리즘 방식이다. 병합 정렬에서는 절반 배열 두 개가 부분 입력이고, 정렬된 두 배열을 합치는 병합이 결합이다. 이진 검색에서는 후보를 절반으로 나누지만 한쪽만 정복하고 결과 결합은 거의 없다.

**기저 조건(base case)**은 더 나누지 않고 답을 직접 내는 가장 작은 입력이다. 배열 길이 0이나 1은 이미 정렬됐으므로 병합 정렬의 기저 조건이다. **종료(termination)**는 모든 허용 입력이 유한 번의 재귀 뒤 기저 조건에 도달한다는 성질이다. 재귀 호출의 입력 크기가 매번 엄격히 줄어드는지 확인해야 한다.

**독립 부분 문제**는 한 부분의 답을 계산할 때 다른 부분의 같은 상태를 다시 요구하지 않는 문제다. 병합 정렬의 왼쪽 인덱스 범위와 오른쪽 범위는 겹치지 않는다. 같은 상태가 여러 경로에서 반복되는 동적 계획법과 구분된다.

## 2. 반열린 구간으로 안전하게 나누기

배열 구간을 [lo, hi)로 쓰면 lo는 포함하고 hi는 제외한다. 원소 수는 hi-lo이고 전체 배열 길이가 n이면 [0,n)이다. 가운데 mid는 (lo+hi)//2다.

~~~text
왼쪽:  [lo, mid)
오른쪽: [mid, hi)
~~~

lo < hi이고 원소가 둘 이상이면 두 구간 모두 원래보다 작다. 길이 1이면 기저 조건에서 멈춘다. [lo,mid]와 [mid,hi]처럼 mid를 양쪽에 포함하면 한 원소가 겹친다. 포함 구간 구현에서 길이 2의 lo=0, hi=1, mid=0인데 오른쪽을 [mid,hi]로 재귀 호출하면 [0,1]이 원래와 같아 종료하지 않는다.

분할은 그림의 선 긋기가 아니라 실제 호출 인자다. 각 호출이 어느 인덱스를 소유하는지, 합칠 때 원소가 한 번씩만 결과에 들어가는지 확인해야 한다.

재귀 종료를 증명할 때는 각 호출에 음이 아닌 정수 **크기 척도**를 붙인다. 반열린 배열 구간의 척도는 hi-lo다. 기저 조건은 척도 0 또는 1이다. 그보다 큰 m을 mid에서 나누면 왼쪽 크기는 mid-lo, 오른쪽은 hi-mid이고 둘 다 1 이상 m 미만이다. 음이 아닌 정수가 호출마다 엄격히 줄어 무한히 이어질 수 없으므로 모든 가지가 기저에 도달한다.

“대체로 절반처럼 보인다”는 설명만으로는 부족하다. 코드의 실제 인자에서 척도가 줄어야 한다. 잘못된 포함 경계 [lo,mid]와 [mid,hi]는 오른쪽 척도가 줄지 않는 크기 2 반례를 만든다. 종료 증명은 정확성 증명의 일부이며 올바른 값을 계산하는 논리와 별도로 확인한다.

## 3. 병합 정렬 코드의 작동 원리

~~~python
def merge(left, right):
    result = []
    i = 0
    j = 0

    while i < len(left) and j < len(right):
        if left[i] <= right[j]:
            result.append(left[i])
            i += 1
        else:
            result.append(right[j])
            j += 1

    result.extend(left[i:])
    result.extend(right[j:])
    return result


def merge_sort(values):
    if len(values) <= 1:
        return list(values)

    middle = len(values) // 2
    left = merge_sort(values[:middle])
    right = merge_sort(values[middle:])
    return merge(left, right)
~~~

merge_sort는 길이 1 이하에서 새 리스트를 돌려준다. 그 외에는 middle을 경계로 복사한 두 조각을 재귀 정렬한다. 두 호출이 끝난 뒤에만 merge를 실행한다. merge의 i와 j는 각 정렬 배열에서 아직 출력하지 않은 첫 위치다. 두 첫 값 중 작은 값을 result에 붙이고 해당 인덱스만 전진한다. 한쪽이 끝나면 다른 쪽 잔여는 이미 정렬되어 있어 그대로 붙인다.

정확성은 입력 길이에 대한 귀납으로 보인다. 길이 0과 1은 정렬됐다. 더 작은 모든 배열을 재귀 호출이 올바르게 정렬한다고 가정하면 left와 right는 정렬됐다. merge가 두 배열의 작은 첫 값을 차례로 고르므로 결과도 정렬되고, 각 원소를 정확히 한 번 옮겨 입력과 같은 다중 집합을 가진다.

## 6. 점화식과 재귀 트리

**점화식(recurrence)**은 크기 n 문제 비용을 더 작은 입력 비용으로 표현한 식이다. 병합 정렬은 절반 두 개와 선형 병합을 수행하므로 다음처럼 쓴다.

~~~text
T(n) = 2T(n/2) + cn
T(1) = d
~~~

c와 d는 입력 크기와 무관한 상수다. **재귀 트리(recursion tree)**는 각 호출을 노드로 그리고 깊이별 작업량을 합하는 분석 도구다.

n=8일 때 병합 원소 처리량을 단순히 크기로 세어 보자.

| 깊이 | 문제 수 | 각 크기 | 깊이의 결합 작업 합 |
| ---: | ---: | ---: | ---: |
| 0 | 1 | 8 | 8 |
| 1 | 2 | 4 | 8 |
| 2 | 4 | 2 | 8 |
| 3 | 8 | 1 | 기저 작업 8 |
| 합 | 없음 | 없음 | 약 8×4 |

비기저 결합 깊이는 log₂8=3개이고 각 깊이 합은 n이다. 따라서 결합 작업은 n log₂n 규모이고 기저 n을 더해도 Θ(n log n)이다. 실제 비교 수는 값 배치에 따라 조금 달라도 각 병합에서 두 입력 길이 합에 비례한다.

n이 2의 거듭제곱이 아니면 T(n)=T(⌊n/2⌋)+T(⌈n/2⌉)+cn으로 쓸 수 있다. 깊이는 ⌈log₂n⌉ 수준이며 각 깊이에서 다루는 총 원소 수는 n 이하라 Θ(n log n) 차수는 유지된다.

재귀 트리에서는 호출 횟수와 호출 밖 작업을 구분한다. 크기 8 병합 정렬의 비기저 호출은 크기 8 하나, 크기 4 둘, 크기 2 넷으로 7개다. 기저 크기 1 호출은 8개다. 호출 수만 세면 15지만, 각 비기저 호출의 병합 비용은 자기 입력 크기에 비례한다. 8+4+4+2+2+2+2=24가 비기저 원소 처리량이다. 따라서 “호출이 15개이니 O(n)”이라고 결론 내리면 호출별 비용을 빠뜨린다.

공간에서는 반대로 모든 트리 노드가 동시에 살아 있지 않다. 왼쪽 재귀가 끝난 뒤 오른쪽을 실행하므로 활성 호출 프레임은 루트에서 현재 잎까지 한 경로다. 크기 8에서는 깊이 0,1,2,3의 네 프레임 수준이다. 결과 배열은 별도로 살아 있을 수 있어 호출 스택 O(log n)과 병합 보조 배열 O(n)을 나누어 센다.

## 7. 마스터 정리의 뜻과 범위

**마스터 정리(master theorem)**는 일정한 수의 같은 비율 부분 문제를 만드는 점화식 T(n)=aT(n/b)+f(n)의 점근 비용을 비교하는 규칙이다. a는 부분 문제 수, b는 축소 비율, f(n)은 분할과 결합 같은 재귀 밖 비용이다.

기준은 n^(log_b a), 즉 잎 수가 자라는 규모와 f(n)을 비교하는 것이다.

- f가 더 작으면 많은 재귀 잎 비용이 지배한다.
- 같은 차수면 깊이마다 비슷한 일이 쌓여 로그 인자가 붙는다.
- f가 충분히 더 크고 정규 조건을 만족하면 루트 쪽 결합 비용이 지배한다.

병합 정렬은 a=2, b=2라 기준 n이고 f(n)=n이라 같은 경우, Θ(n log n)이다. 이진 검색은 a=1, b=2, 기준 1, f(n)=1이라 Θ(log n)이다.

모든 점화식에 적용할 수 없다. T(n)=T(n-1)+n은 일정 비율 n/b로 줄지 않는다. 크기가 서로 매우 다른 부분 문제, 불규칙한 f, 추가 조건을 만족하지 않는 식도 재귀 트리나 치환법으로 직접 분석해야 한다.

2의 거듭제곱이 아닌 n=6 병합 정렬도 살펴보자. 길이만 적으면 6은 3과 3, 각 3은 1과 2, 각 2는 1과 1로 나뉜다.

| 깊이 | 부분 크기 | 그 깊이 총크기 |
| ---: | --- | ---: |
| 0 | 6 | 6 |
| 1 | 3,3 | 6 |
| 2 | 1,2,1,2 | 6 |
| 3 | 크기 2에서 나온 1,1,1,1 | 4 |

모든 가지 깊이가 정확히 같지는 않지만 최대 깊이는 ⌈log₂6⌉ 수준이다. 각 깊이의 총 결합 대상은 6 이하이고 깊이가 로그 규모라 Θ(n log n)이다. 바닥과 천장 함수는 세부 호출 크기를 바꾸지만 점근 차수를 바꾸지 않는다.

## 8. 이진 검색의 한쪽 재귀 추적

재귀 구현은 후보 구간을 실제 인자로 전달한다.

~~~python
def binary_search(keys, target, lo=0, hi=None):
    if hi is None:
        hi = len(keys)
    if lo >= hi:
        return None

    mid = (lo + hi) // 2
    if keys[mid] == target:
        return mid
    if keys[mid] < target:
        return binary_search(keys, target, mid + 1, hi)
    return binary_search(keys, target, lo, mid)
~~~

첫 호출만 hi를 배열 길이로 만든다. lo>=hi는 빈 반열린 구간의 기저 조건이다. mid 값이 작으면 mid까지 검사해 버렸으므로 mid+1부터, 크면 mid를 제외하는 오른쪽 경계 hi=mid로 재귀한다. 각 호출의 구간 길이는 이전의 절반 이하로 줄고 반환값 결합은 그대로 전달하는 일뿐이다.

정렬 배열 [3,8,12,20,31,44,57,91]에서 43을 찾는다. 반열린 후보 [lo,hi)를 쓴다.

| 호출 | 후보 구간 | mid | 값 | 다음 호출 |
| ---: | --- | ---: | ---: | --- |
| 1 | [0,8) | 4 | 31 | 43이 크므로 [5,8) |
| 2 | [5,8) | 6 | 57 | 43이 작으므로 [5,6) |
| 3 | [5,6) | 5 | 44 | 43이 작으므로 [5,5) |
| 4 | [5,5) | 없음 | 후보 없음 | 부재 반환 |

후보 크기는 8→3→1→0으로 줄었다. 이진 검색은 두 절반을 모두 풀지 않고 target이 있을 수 있는 한쪽만 정복한다. 점화식은 T(n)=T(n/2)+O(1)이고 재귀 트리에는 깊이마다 호출 하나만 있어 Θ(log n)이다. 결합은 하위 반환값을 그대로 전달하는 상수 작업이다.

정렬 전제가 없으면 가운데 비교로 한쪽을 버릴 근거가 사라진다. 분할 정복이라는 구조가 선조건을 대신하지 않는다.

## 9. 빠른 거듭제곱과 중복 호출 반례

x^n을 계산할 때 n을 절반으로 줄인다.

~~~python
def power(base, exponent):
    if exponent < 0:
        raise ValueError("exponent must be non-negative")
    if exponent == 0:
        return 1

    half = power(base, exponent // 2)
    if exponent % 2 == 0:
        return half * half
    return base * half * half
~~~

power(2,5)의 호출은 지수 5→2→1→0이고 반환은 1→2→4→32다. 짝수 n은 (x^(n/2))², 홀수 n은 x×(x^⌊n/2⌋)²라는 항등식을 쓴다. exponent//2가 0에 가까워져 종료한다. 호출 깊이와 시간은 O(log n)이다.

half를 변수에 저장하지 않고 power(base,n//2)를 곱셈 양쪽에서 두 번 부르면 같은 부분 문제를 중복 계산한다. 점화식이 T(n)=2T(n/2)+O(1)로 바뀌어 Θ(n) 규모가 된다. 코드 한 줄의 중복 호출이 재귀 트리 가지 수를 바꾼다.

마스터 정리의 세 비교를 재귀 트리 작업으로 읽어 보자.

| 점화식 | 깊이별 작업 변화 | 지배하는 곳 | 결과 |
| --- | --- | --- | --- |
| 4T(n/2)+n | n, 2n, 4n, … | 잎 쪽 | Θ(n²) |
| 2T(n/2)+n | n, n, n, … | 모든 깊이 | Θ(n log n) |
| 2T(n/2)+n² | n², n²/2, n²/4, … | 루트 쪽 | Θ(n²) |

첫 식은 부분 문제 수가 빠르게 늘어 잎 개수 n²가 지배한다. 둘째는 각 깊이 합이 같아 로그 개수만큼 누적된다. 셋째는 자식 전체 결합 비용이 부모의 절반으로 줄어 기하급수 합이 루트 n²의 상수배에 머문다. 공식을 기억하기보다 한두 깊이의 “문제 수×각 비용”을 계산하면 어느 쪽이 커지는지 확인할 수 있다.

## 10. 퀵 정렬의 분할 품질

퀵 정렬은 피벗보다 작은 구간과 큰 구간을 정복하고 분할에 Θ(n)을 쓴다. 피벗이 중간 크기에 가까우면 T(n)=2T(n/2)+Θ(n)이라 Θ(n log n)이다. 매번 최솟값이면 한쪽 크기 0, 다른 쪽 n-1이라 T(n)=T(n-1)+Θ(n)이고 n+(n-1)+…+1=Θ(n²)이다.

무작위 피벗은 고정된 입력에서 계속 치우칠 확률을 낮춰 기대 성능을 개선하지만 최악 입력 경로가 사라지는 것은 아니다. “평균”이면 입력 분포를, “기대”이면 알고리즘의 무작위 선택을 확률 대상으로 명시해야 한다.

### 최대 부분 배열의 결합을 실제로 보기

배열 [-2,1,-3,4,-1,2,1,-5]에서 연속 구간 합이 최대인 부분을 찾는 분할 정복을 생각하자. 전체 답은 왼쪽 절반 안, 오른쪽 절반 안, 가운데 경계를 가로지르는 경우 중 하나다.

왼쪽 [-2,1,-3,4]의 최선은 [4]로 합 4다. 오른쪽 [-1,2,1,-5]의 최선은 [2,1]로 합 3이다. 경계를 가로지르는 답은 왼쪽의 경계에서 끝나는 최선 접미사와 오른쪽의 경계에서 시작하는 최선 접두사를 붙인다.

| 스캔 | 누적 합 | 지금까지 최선 |
| --- | ---: | ---: |
| 왼쪽 4 | 4 | 4 |
| 왼쪽 -3 추가 | 1 | 4 |
| 왼쪽 1 추가 | 2 | 4 |
| 왼쪽 -2 추가 | 0 | 4 |
| 오른쪽 -1 | -1 | -1 |
| 오른쪽 2 추가 | 1 | 1 |
| 오른쪽 1 추가 | 2 | 2 |
| 오른쪽 -5 추가 | -3 | 2 |

가로지르는 합은 4+2=6이고 구간은 [4,-1,2,1]이다. 세 후보 4,3,6 중 6을 고른다. 결합에서 각 절반을 경계부터 한 번 훑어 Θ(n), 점화식은 2T(n/2)+Θ(n)이라 Θ(n log n)이다. 그러나 같은 문제에는 한 번 훑는 Θ(n) 알고리즘도 있어 분할 정복이 최적 선택을 자동 보장하지 않는다.

## 11. 분할 정복과 동적 계획법, 병렬성

병합 정렬의 좌우 구간은 독립이라 동시에 계산할 가능성이 있다. 그러나 작업 생성, 배열 복사, 결과 이동, 최종 병합은 비용이 든다. 작은 부분까지 무한히 병렬 작업으로 만들면 관리 비용이 계산보다 커질 수 있어 임계 크기 아래에서는 순차 실행하는 정책이 필요하다.

피보나치 단순 재귀처럼 f(n-1)과 f(n-2)가 다시 같은 f(n-3)을 요구하면 부분 문제가 겹친다. 매번 새 호출하면 재귀 트리가 중복으로 커진다. 메모이제이션이나 표 채우기로 같은 상태 답을 재사용하는 동적 계획법이 적합하다.

분할 정복이 자동으로 가장 빠른 것도 아니다. 최대 부분 배열은 분할 정복 O(n log n)으로 풀 수 있지만 한 번 훑는 Kadane 알고리즘 O(n)도 있다. 알고리즘 구조와 최선 비용을 같은 말로 쓰면 안 된다.

점화식을 직접 펼치는 것도 검산 방법이다. 병합 정렬 식에서 T(n/2)를 한 번 대입하면 2[2T(n/4)+c(n/2)]+cn = 4T(n/4)+2cn이다. k번 뒤 2^k T(n/2^k)+kcn이 된다. n/2^k=1일 때 k=log₂n이고 첫 항은 nT(1), 둘째는 cn log₂n이다. 둘을 합쳐 Θ(n log n)이다.

이진 검색은 T(n)=T(n/2)+c를 k번 펼치면 T(n/2^k)+kc다. 같은 k=log₂n에서 T(1)+c log₂n이므로 Θ(log n)이다. 전개는 재귀 트리 표와 같은 계산을 식으로 확인한 것이다.

## 12. 공간 비용

전형적 병합 정렬은 병합 결과와 슬라이스에 O(n) 추가 배열 공간을 쓴다. 동시에 활성인 재귀 호출 깊이는 O(log n)이다. 제자리 퀵 정렬도 배열 보조 공간은 작지만 호출 스택은 균형 분할 O(log n), 치우친 분할 O(n)이 될 수 있다.

시간 점화식만 쓰면 메모리 최고 동시 사용량을 놓친다. 부분 호출 두 개가 순차 실행되는지 동시에 실행되는지, 결과 배열이 언제 해제되는지에 따라 실제 최고 공간이 달라진다.

## 13. 확인 문제와 자세한 풀이

### 문제 1. 8개 병합 비용

크기 8 병합 정렬의 비기저 깊이 수와 깊이별 총 처리 원소 수를 구하라.

**풀이.** 8→4→2→1로 세 번 나누므로 비기저 병합 깊이는 3개다. 크기 2 병합 네 개는 총 8, 크기 4 병합 두 개도 총 8, 크기 8 병합 하나도 8을 처리한다. 합은 24 규모이고 일반화하면 n log₂n이다. 기저 호출 8개의 상수 작업을 더해도 Θ(n log n)은 바뀌지 않는다.

### 문제 2. 경계 중복과 종료

포함 구간 [lo,hi]에서 left=[lo,mid], right=[mid,hi]로 나누면 길이 2에서 왜 종료하지 않을 수 있는가?

**풀이.** lo=0, hi=1이면 mid=0이다. left=[0,0]은 작지만 right=[0,1]은 원래 구간과 같다. 오른쪽 재귀가 같은 인자로 다시 호출되어 기저 조건에 가까워지지 않는다. 올바른 포함 구간은 right=[mid+1,hi]이고, 반열린 구간이면 [lo,mid), [mid,hi)를 쓴다.

### 문제 3. 이진 검색 점화식

이진 검색이 T(n)=2T(n/2)+1이 아니라 T(n)=T(n/2)+1인 이유를 설명하라.

**풀이.** 가운데 값과 target을 비교하면 정렬성 때문에 target이 있을 수 없는 절반을 버린다. 남은 한 절반만 재귀 호출한다. 두 절반 모두 검색하면 답은 찾을 수 있어도 선형 규모가 되어 이진 검색의 이점을 잃는다. 깊이마다 호출 하나, 후보가 절반이라 Θ(log n)이다.

### 문제 4. 빠른 거듭제곱 중복

power(x,n//2)를 두 번 호출하는 코드와 half에 한 번 저장하는 코드의 점화식과 n=8 호출 수 차이를 설명하라.

**풀이.** 저장 코드는 지수 8,4,2,1,0의 한 경로로 T(n)=T(n/2)+O(1), 호출 5개다. 두 번 호출하면 각 비기저 호출이 자식 둘을 만들어 T(n)=2T(n/2)+O(1)이다. n=8에서 깊이별 1,2,4,8 호출과 기저가 생겨 Θ(n) 규모다. 같은 숫자 답을 내도 계산량은 다르다.

### 문제 5. 마스터 정리 적용 가능성

T(n)=3T(n/3)+n과 T(n)=T(n-1)+n을 비교하라.

**풀이.** 첫 식은 a=3, b=3, 기준 n^(log₃3)=n이고 f(n)=n이라 같은 차수다. 깊이 log₃n마다 n 일이 있어 Θ(n log n)이다. 둘째는 n/b 비율로 줄지 않고 1만 감소하므로 표준 마스터 정리 형태가 아니다. 직접 펼치면 n+(n-1)+…+1=Θ(n²)이다.

### 문제 6. 퀵 정렬 악조건

정렬 배열에서 첫 원소를 피벗으로 고를 때 분할 크기와 공간이 어떻게 변하는가?

**풀이.** 피벗보다 작은 값은 0개, 큰 값은 n-1개라 호출 크기가 n-1,n-2로 한 칸씩 줄어든다. 시간은 Θ(n²)이고 동시에 활성인 호출 깊이도 Θ(n)이 되어 스택 공간 O(n)이다. 균형 분할이면 시간 Θ(n log n), 스택 O(log n)이다.

### 문제 7. 독립성과 겹침

병합 정렬과 단순 피보나치 재귀의 부분 문제 차이를 설명하라.

**풀이.** 병합 정렬의 왼쪽과 오른쪽 인덱스 범위는 겹치지 않고 각 원소는 한 갈래에만 속한다. 피보나치 f(n-1)과 f(n-2)는 내부에서 같은 f(n-3), f(n-4)를 반복 요청한다. 전자는 각 답을 결합하는 분할 정복이 자연스럽고, 후자는 상태별 답을 저장하는 동적 계획법으로 중복을 제거해야 한다.

### 결합 단계의 계약을 따로 검사하기

분할 정복의 각 재귀 호출이 맞더라도 결합 코드가 부분 답을 빠뜨리면 전체 답은 틀린다. 따라서 결합 단계에는 별도 계약이 필요하다. 병합 정렬이라면 입력 두 배열이 각각 정렬되어 있고, 출력에는 두 입력의 모든 원소가 정확히 한 번씩 있어야 하며, 출력 순서는 오름차순이어야 한다. 원소 수가 보존되는지, 최솟값이 첫 칸에 놓이는지, 같은 키의 순서가 보존되는지를 작은 입력으로 점검하면 분할 코드와 결합 코드를 구분해 진단할 수 있다. 이 검사는 귀납 증명에서 “작은 두 답이 옳다” 다음에 “결합한 답도 옳다”를 보이는 부분과 정확히 대응한다.

## 14. 구현 점검표

기저 조건, 각 재귀 입력의 엄격한 크기 감소, 부분 범위의 겹침과 누락, 결합의 정답 보존을 확인한다. 점화식에는 부분 문제 수와 크기, 재귀 밖 비용을 모두 넣는다. 시간과 호출 스택·보조 배열 공간을 분리한다. 0개, 1개, 2개, 홀수 길이, 이미 정렬, 역순 입력을 손으로 추적한다.

## 참고

분할 정복의 비용은 함수 이름이 아니라 실제 호출 수와 각 깊이의 작업 합으로 계산한다. 마스터 정리는 형태와 정규 조건이 맞는 점화식에만 적용한다.
